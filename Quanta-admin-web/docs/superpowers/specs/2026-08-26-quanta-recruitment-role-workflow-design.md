# Quanta 招新角色与评定流程调整规格

日期：2026-08-26  
状态：最终设计已由用户确认  
涉及模块：招新管理、动态菜单、成员管理按钮权限

## 1. 目标与边界

本阶段调整管理层与经理层在招新管理中的页面操作和评定流程，同时完善经理层动态菜单。成员管理的高风险权限不扩张：删除和重置密码仍只有 CEO 可以使用。

本阶段继续使用现有 Mock 数据和 API 适配层，不等待后端上线。真实接口接入后，后端仍需校验角色、按钮权限和部门数据范围。

## 2. 角色权限矩阵

### 2.1 管理层（含 CEO）

- 成员管理：普通管理层只读；CEO 可删除成员和重置密码。
- 招新一面：阅览简历、查看面评，并在查看面评流程中执行 Pass/Out。
- 招新二面：只显示“是否录用”，负责最终 Pass/Out 与通知发送。
- 普通管理层只操作本部门志愿；CEO 保留查看全部部门志愿的能力。

### 2.2 经理层

- 成员管理：只读，不能删除、重置密码或执行其他高风险操作。
- 招新一面：阅览简历、编辑面评，并显示“已评”状态；不能 Pass/Out。
- 招新二面：只显示“编辑面评”；不能阅览简历、Pass/Out 或录用。
- 一面和二面数据均严格限制为本部门志愿。

### 2.3 按钮权限

继续采用若依按钮权限码作为能力来源，并叠加角色约束：

- `recruitment:resume:view`：阅览简历。
- `recruitment:feedback:view`：管理层查看面评。
- `recruitment:feedback:edit`：经理层编辑面评。
- `recruitment:decision`：管理层一面 Pass/Out。
- `recruitment:offer`：管理层二面录用评定和通知。
- `member:remove`、`member:resetPwd`：必须同时拥有权限码和 `ceo` 角色。

前端按钮隐藏用于交互分流，后端必须执行相同的权限和部门数据校验。

## 3. 动态菜单

经理层菜单以已确认设计图为准，显示：

- 控制台
- 成员管理
- 招新管理
- 学习资料
- 图书借阅

经理层不显示工位预约和塔服订购。其他角色继续使用现有动态菜单配置，不在本阶段扩大调整范围。

## 4. 表格视觉调整

- 第一志愿、第二志愿中的部门胶囊缩小：内边距约为 `2px 6px`，字体缩小一级，保持现有第一/第二志愿配色。
- “阅览简历”“查看面评”“编辑面评”“是否录用”均增加下划线。
- 下划线颜色使用对应文字颜色，不使用统一黑色。
- 管理层一面移除表格中的独立“评定”入口。
- Pass/Out 结果继续沿用已确认的纯文字样式。

## 5. 管理层一面流程

### 5.1 表格操作

操作区只保留：

- 阅览简历：打开现有只读简历弹窗。
- 查看面评：打开只读面评弹窗。

“已评”可作为非操作状态继续显示，但不替代查看面评入口。

### 5.2 查看面评

查看面评弹窗展示选中志愿及已有面评列表，不显示评价输入框和保存按钮。普通管理层只能看到本部门志愿；CEO 可在其可见志愿之间切换。

底部按钮为取消、Out、Pass，不提供 Waiting。点击 Out 或 Pass 时，不立即调用接口，而是记录选中结果并切换到一面确认弹窗。

### 5.3 一面结果确认

确认弹窗展示：

- 候选人姓名。
- 已选择的 Pass 或 Out。
- 当前志愿下拉框，处于锁定状态。
- 取消、确认按钮。

取消后返回名单，不提交结果；确认后调用现有一面结果接口。Pass 按既有双志愿规则进入二面，Out 终止当前志愿轨道。两个志愿均进入二面时，仍默认第一志愿进入，规则不变。

## 6. 经理层面评流程

经理层使用可编辑面评弹窗：

- 志愿锁定为当前经理所属部门。
- 展示已有面评历史。
- 提供面评输入框和提交按钮。
- 一面提交后显示“已评”状态。
- 二面名单操作区只保留带下划线的“编辑面评”。

保存面评只更新评价内容，不改变候选人的 Pass/Out 或录用状态。

## 7. 管理层二面流程

### 7.1 表格操作

二面操作区只显示带下划线的“是否录用”。不显示阅览简历、查看面评或独立评定入口。

### 7.2 二面确认弹窗

点击“是否录用”先进入二面结果确认弹窗。弹窗参考已提供设计稿，包含标题、确认提示、锁定的志愿下拉框、取消和确认按钮。

点击取消关闭弹窗且不修改状态。点击确认后关闭确认弹窗，并打开通知编辑弹窗；此时仍未发送通知。

### 7.3 通知编辑弹窗

通知弹窗保留“是否录用 / 查看面评”的布局，并展示：

- Pass、Out 选择按钮。
- 接收人。
- 锁定的志愿下拉框。
- 可编辑的通知内容。
- 取消、发送通知按钮。

选择 Pass 时自动填充录用通知模板；选择 Out 时自动填充淘汰通知模板。用户可以在发送前修改文案。点击发送通知后提交最终结果和通知，成功后关闭弹窗并刷新名单与统计。

## 8. 组件与状态设计

- 候选人表格只根据角色、轮次和权限发出语义事件，不直接调用 API。
- 查看面评与编辑面评分离为只读和可编辑模式，避免管理层误修改评价。
- 一面确认弹窗只负责确认已选择结果，不再次提供 Pass/Out，防止重复选择。
- 二面确认弹窗与通知弹窗保持两个独立步骤，由招新页面维护当前候选人、志愿、结果和弹窗状态。
- 关闭任一弹窗时清理临时结果，避免下一个候选人继承旧状态。

## 9. 接口与异常处理

- 查看面评继续调用评价列表接口，不调用保存接口。
- 编辑面评继续调用评价保存接口。
- 一面确认调用面试结果接口，结果仅允许 `PASS` 或 `FAIL`。
- 二面发送需要同时持久化最终结果和通知。若现有通知接口不能保证二者一致，前端 Mock 先模拟完整事务，并把“二面结果与通知原子提交接口”记录为缺失后端能力。
- 所有提交期间禁用关闭和重复提交。
- 加载评价失败时保留弹窗并提供错误提示；结果或通知提交失败时保留用户已选志愿、结果和通知内容，允许重试。
- 401、403 和部门越权继续交由统一请求层处理。

## 10. 测试与验收

- 管理层一面仅显示阅览简历、查看面评；查看面评只读并提供 Pass/Out。
- 一面点击 Pass/Out 后出现锁定志愿的确认弹窗，取消不提交，确认正确提交结果。
- 管理层二面只显示是否录用；确认后进入通知弹窗，Pass/Out 正确切换模板。
- 经理层一面显示阅览简历、编辑面评和已评状态；二面只显示编辑面评。
- 经理层看不到任何评定或录用动作。
- 普通管理层和经理层都不能越权查看或操作其他部门志愿。
- CEO 成员管理仍显示删除和重置密码，其他管理层及经理层均不显示。
- 经理层菜单显示图书借阅，不显示工位预约和塔服订购。
- 部门胶囊尺寸、所有指定操作下划线和弹窗视觉通过浏览器截图验收。
- 完整测试、ESLint、生产构建和浏览器控制台检查通过。
