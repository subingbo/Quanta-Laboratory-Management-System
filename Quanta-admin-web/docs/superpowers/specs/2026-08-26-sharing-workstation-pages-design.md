# 精英分享会与工位预约只读页面设计规格

## 1. 目标与范围

本批次把动态导航中已有的“精英分享会”和“工位预约”从统一占位页替换为真实只读业务页面，同时完成招新弹窗的三项视觉与文案微调。

本批次不增加搜索、导出、编辑、删除、审批、取消预约、工位维护、分页控件或新增预约功能。后端尚未上线时由现有 Mock 请求层提供可交互数据；后端上线后页面通过 API 适配层切换，不重写视图。

## 2. 动态路由与权限

- 保留现有路径、菜单标题、图标和分组：
  - `/sharing-signups` → `精英分享会`
  - `/workstations` → `工位预约`
- 将路由组件键从 `placeholder/index` 分别改为：
  - `sharing-signups/index`
  - `workstations/index`
- 在动态组件映射表注册这两个新页面，不新增重复菜单。
- CEO、管理员、只读塔员沿用现有权限。
- 产品部和设计部管理层补充 `activity:list` 与 `reservation:list`，使其能看到并访问两个页面。
- 经理层继续不拥有 `activity:list` 和 `reservation:list`，因此不显示精英分享会和工位预约；这与此前确认的经理层导航保持一致。
- 路由守卫和按钮权限机制不做特殊分支，继续依赖现有动态路由过滤与权限码。

## 3. 精英分享会报名名单

### 3.1 页面结构

- 页面标题沿用动态路由标题“精英分享会”。
- 内容区使用现有 `page-card` 白色圆角卡片与紧凑业务表格规范。
- 卡片标题为“精英分享会报名名单”。
- 标题右侧紧邻人数徽标，固定展示 `10 / 50`；前者是报名人数，后者是活动名额。
- 表格字段顺序：序号、姓名、联系方式、报名时间、备注留言。
- 电话按接口返回的脱敏字符串直接展示，不在前端二次处理。
- 无操作列。

### 3.2 临时接口契约

后端接口缺失，本地先建立：

```http
GET /qt/activity/sharing/registrations
```

返回若依列表结构：

```json
{
  "code": 200,
  "msg": "操作成功",
  "rows": [
    {
      "registrationId": 1,
      "name": "陈佳琪",
      "contact": "138****1234",
      "registeredAt": "2025-10-05 09:00",
      "remark": "对AI方向感兴趣"
    }
  ],
  "total": 10,
  "quota": 50
}
```

Mock 提供 10 条记录，使报名人数与表格总数一致。真实后端上线前，此接口保留在缺失接口清单中。

### 3.3 状态处理

- 加载中使用 Element Plus 表格加载状态。
- `rows` 为空时显示“暂无报名记录”。
- 请求失败时在卡片内显示“报名名单暂时无法加载”与“重新加载”按钮。
- 页面只读，不产生写请求。

## 4. 工位预约记录

### 4.1 页面结构

- 页面标题沿用动态路由标题“工位预约”。
- 卡片标题为“工位预约记录”。
- 表格字段顺序：预约人、工位号、日期、时间段、状态。
- 工位号使用浅橙色紧凑标签。
- 状态使用紧凑标签，不显示操作列。

### 4.2 现有接口

```http
GET /system/reservation/detailList
```

本管理页面不传 `userId`，展示接口返回的预约记录。页面只消费以下字段：

- `reservationId`
- `nickName`，缺失时回退 `userName`
- `workstationCode`
- `reserveStart`
- `reserveEnd`
- `status`

Mock 使用 8 条与设计稿一致的预约记录。

### 4.3 日期与状态映射

- `reserveStart` 的日期部分显示为 `YYYY-MM-DD`。
- 同一天的起止时间组合为 `HH:mm-HH:mm`。
- 若起止时间跨日，时间段显示完整的结束日期时间，避免误导。
- 状态映射：
  - `PENDING` → 待审核，橙色
  - `APPROVED` → 已预约，橙色
  - `CANCELED` → 已取消，蓝灰色
  - `FINISHED` → 已完成，绿色
  - 未知值 → 原值或“-”，灰色

### 4.4 状态处理

- 加载中使用 Element Plus 表格加载状态。
- `rows` 为空时显示“暂无预约记录”。
- 请求失败时在卡片内显示“预约记录暂时无法加载”与“重新加载”按钮。
- 页面不暴露新增、审批、取消、删除或导出功能。

## 5. 招新弹窗微调

- 二面确认文案修改为：`确定向该同学(姓名)发送二面是否通过的录用通知？`。
- 一面查看面评弹窗中的 Pass/Out 字号从 `12px` 调整为 `14px`。
- 二面录用通知弹窗中的 Pass/Out 字号从 `12px` 调整为 `14px`。
- 其他 Pass/Out 尺寸、颜色、顺序和交互保持不变。
- “是否录用 / 查看面评”当前页签下方指示线使用：
  - 宽度 `44px`
  - 高度 `3px`
  - 颜色 `#FF6600`
  - 水平居中于当前页签文字下方
- 不使用设计稿中的绝对页面坐标 `top/left`，以确保弹窗在不同分辨率和缩放比例下稳定居中。

## 6. 文件边界

- `src/api/sharing-signups.js`：精英分享会只读接口适配。
- `src/api/workstations.js`：工位预约列表接口适配与查询参数传递。
- `src/mock/data/sharing-signups.js`：精英分享会 Mock 数据。
- `src/mock/data/workstations.js`：工位预约 Mock 数据。
- `src/mock/handlers/sharing-signups.js`：精英分享会 Mock handler。
- `src/mock/handlers/workstations.js`：工位预约 Mock handler。
- `src/views/sharing-signups/index.vue` 与同目录 CSS：精英分享会页面。
- `src/views/workstations/index.vue` 与同目录 CSS：工位预约页面。
- 现有招新组件与 CSS 仅做本规格列出的微调，不重构已完成流程。

## 7. 测试与验收

- API 测试验证两个列表适配器正确解包若依 `rows/total`，并保留精英分享会 `quota`。
- Mock handler 测试验证登录与权限校验、成功列表结构。
- 路由转换测试验证两个组件键能解析且不再进入占位页。
- 页面测试验证标题、人数 `10 / 50`、列内容、状态映射、空状态和失败重试。
- 招新组件测试验证新文案和 CSS 语义类不回退。
- 全量 Vitest、ESLint 和 Vite 构建通过。
- 浏览器分别使用管理层账号检查两项菜单、两个只读页面和招新弹窗最终效果；控制台不得出现错误。
