# 招新管理评定弹窗样式与交互规格

## 目标

在不改变现有权限、接口参数和招新业务流程的前提下，统一一面结果状态、查看面评弹窗与二面录用弹窗的视觉语言，并把二面通知编辑器改造成“是否录用 / 查看面评”两个可切换页签。

## 一面名单与查看面评

- 表格内 Pass/Out 继续保持纯文字，不使用胶囊或色块背景。
- Pass 使用 `#05C860`，Out 使用 `#FF0404`。
- Pass/Out 字体优先使用 `Inter`，字重 `500`，字号 `12px`，行高 `19.5px`。
- 查看面评弹窗底部操作顺序为左侧 Pass、右侧 Out。
- 弹窗 Pass/Out 使用白字实色按钮，背景分别为 `#05C860` 和 `#FF0404`。

## 二面结果确认

- 点击“是否录用”后先展示确认弹窗，并保留锁定的志愿选择框。
- 提示文案为：`确定向该同学(姓名)发送二面通过的录用通知？`，其中姓名使用当前候选人姓名替换。
- 底部按钮顺序为取消、确认；取消使用 `#FF0404` 红底白字，确认使用 `#05C860` 绿底白字。
- 点击确认后进入通知编辑弹窗，不立即调用发送接口。

## 二面通知编辑弹窗

- 顶部提供“是否录用”和“查看面评”两个可点击页签，当前页签使用橙色下划线指示。
- “是否录用”页展示 Pass/Out 选择、接收人、锁定志愿、通知内容以及发送操作。
- Pass 在左、Out 在右；选中 Pass 使用 `#05C860`，选中 Out 使用 `#FF0404`，未选中项使用中性灰。
- 切换 Pass/Out 时沿用现有逻辑自动更新通知模板。
- “查看面评”页只读展示当前候选人、当前锁定志愿在二面阶段的面评记录；没有记录时展示明确空状态。
- 查看面评页不展示发送按钮，切回“是否录用”后保留已选择的结果和编辑过的通知内容。
- 弹窗按钮与状态文字保持紧凑，避免设计稿中控件显得过大的问题。

## 数据与权限边界

- 二面面评通过现有 `getEvaluations({ applicationId, roundId: 2, department })` 获取。
- 发送仍使用现有 `sendOffer`，参数结构保持不变。
- 管理层和经理层的权限、部门范围及菜单可见性保持当前实现，不在本次修改中调整。
- 后端不可用时继续使用现有 mock 数据与请求适配层。

## 验收标准

- 组件测试覆盖状态颜色类、按钮顺序、确认文案、页签切换、面评空状态和事件触发。
- 招新相关测试、全量测试、ESLint 和生产构建全部通过。
- 在浏览器中分别检查管理层一面查看面评和二面录用完整流程，确认无溢出、错位或不可点击控件。
