# Quanta 成员管理模块设计规格

日期：2026-08-24  
状态：方案已由用户确认，等待书面规格复核  
对应底座：`docs/superpowers/specs/2026-08-24-quanta-admin-foundation-design.md`

## 1. 目标与边界

本阶段在现有 Vue 3、Element Plus、Pinia、Vue Router 与若依兼容数据层之上，完成成员管理页面及其完整前端交互。后端尚未上线，因此所有流程先通过 Mock 可操作演示；真实接口上线后通过环境变量切换，不重写页面。

本阶段包含姓名搜索、届次切换、部门/角色筛选、名单导入、删除、重置密码、留任确认、跨届同步、按钮权限、加载/空/错误状态和自动化测试。

每年 8 月 1 日的自动卸任与届次结转属于后端定时任务，本阶段前端不使用本地日期篡改正式业务状态。

## 2. 已确认业务规则

- 成员按届次分组，页签由接口动态返回，并明确一个当前届。
- 角色筛选分为管理层、经理层、实习生。管理层包含 O 字辈与 VP。
- 当前届成员显示在职状态，可按权限删除或重置密码。
- 历史届成员可显示已卸任或已留任；符合条件且尚未确认者显示“是否留任”。
- 点击“是否留任”先二次确认。
- 确认留任后，原届记录保留并更新为“已留任”。
- 若下一届不存在，后端创建下一届；随后把该成员同步到下一届，并在新届显示为“在职”。
- 每年 8 月 1 日，管理层自动变为已卸任；经理层和实习生若未在此前确认留任，也自动变为已卸任。该规则由后端保证幂等执行。
- 导入成功显示反馈；正式名单模板由用户后续提供。
- 删除前显示确认弹窗；重置成功显示反馈。

## 3. 方案选择

采用“成员业务适配层”方案：页面只依赖稳定的前端成员模型，API 模块负责把若依 `SysUser` 与成员专用接口转换为该模型。

已有能力优先复用若依接口：

- 成员列表：`GET /qt/member/list`
- 用户导入：`POST /system/user/importData`
- 导入模板：`POST /system/user/importTemplate`
- 删除用户：`DELETE /system/user/{userIds}`
- 重置密码：`PUT /system/user/resetPwd`

届次和留任目前不在 Apifox 中，先定义推荐契约并由 Mock 实现。页面不直接散落若依字段，因此后端最终路径或字段有调整时，只修改 `src/api/members.js` 和映射函数。

## 4. 前端模块结构

```text
src/
  api/members.js
  mock/data/members.js
  mock/handlers/members.js
  views/members/
    index.vue
    members.css
    components/
      MemberFilters.vue
      CohortTabs.vue
      MemberTable.vue
      ImportMembersDialog.vue
  views/members/__tests__/
  api/__tests__/members.test.js
```

页面负责查询条件、对话框和表格展示；API 适配层负责请求与字段转换；Mock Handler 负责模拟若依响应和留任事务；通用权限仍复用现有 `v-permission`、`usePermission` 和 `PermissionButton`。

## 5. 页面与交互设计

### 5.1 页面布局

页面继续复用现有后台外壳。内容区使用一张白色主卡片：

1. 顶部工具栏左侧为姓名搜索框，右侧为“导入名单”。
2. 第二行为届次胶囊页签，当前届标注“（当前）”。
3. 下方为成员表格；表头部门与角色提供筛选入口。
4. 表格宽度不足时仅表格区域横向滚动，布局和侧栏不被撑开。

视觉沿用设计稿的深蓝、橙色、浅灰和语义状态色，并复用现有 CSS 变量，不建立第二套主题。

### 5.2 查询与筛选

- 姓名搜索采用输入后 300ms 防抖，清空时恢复列表。
- 切换届次立即重新查询，并清空当前页码；姓名与筛选条件保留，方便跨届对比。
- 部门筛选项由成员查询元数据返回，避免前端写死组织结构。
- 角色筛选值固定为 `management`、`manager`、`intern`，显示为管理层、经理层、实习生。
- 查询参数由 API 适配层转换为后端最终接受的字段。
- 第一版增加分页能力；数据少时分页器自动隐藏。

### 5.3 当前届表格

列为姓名、部门、角色、届数、联系电话、加入时间、状态和操作。手机号使用后端返回的脱敏值；前端不持有完整手机号。

状态默认显示“在职”。操作包括：

- 删除：需要 `member:remove`；弹窗展示成员姓名，确认后删除并刷新当前查询。如果删除后当前分页为空，则回退一页。
- 重置密码：需要 `member:resetPwd`；调用后端安全策略，不在前端写死或展示固定默认密码，成功后显示提示。

### 5.4 历史届表格

历史届沿用相同主要列。状态与操作规则：

- `resigned`：显示“已卸任”，无留任操作。
- `retained`：显示“已留任”，无重复操作。
- `retention_pending`：拥有 `member:retain` 权限时显示“是否留任”。

确认留任后，Mock 以一次事务完成：更新原记录、创建下一届（如需要）、复制成员到下一届。页面随后刷新届次列表和当前表格，因此新页签会立即出现。

### 5.5 名单导入

“导入名单”需要 `member:import` 权限。对话框支持拖拽或选择 `.xls`、`.xlsx` 文件，限制单文件与合理大小，阻止错误类型提交。

上传使用 `multipart/form-data`，保留若依常用 `updateSupport` 参数，默认不覆盖已存在成员。成功后关闭弹窗、清空文件并刷新列表；部分失败时展示后端摘要，不把失败记录误报为成功。

模板文件尚未提供。前端保留下载模板 API 和入口能力；在模板确认前，Mock 返回“模板待提供”的明确提示，不伪造正式 Excel 模板。

## 6. 权限设计

- `member:list`：访问页面和查询列表。
- `member:import`：显示导入名单入口。
- `member:remove`：显示删除按钮。
- `member:resetPwd`：显示重置密码按钮。
- `member:retain`：显示是否留任按钮并允许提交。

Mock 管理员继续使用超级权限 `*:*:*`。只读账号只拥有 `member:list`，因此能搜索、筛选和切换届次，但看不到任何写操作。按钮隐藏只改善体验，真实接口仍必须由后端校验权限。

## 7. 稳定前端数据模型

成员列表项统一转换为：

```js
{
  id,
  name,
  department,
  roleCode,
  roleLabel,
  cohort,
  phoneMasked,
  joinedAt,
  status,
  canRetain
}
```

列表响应统一为：

```js
{
  rows,
  total,
  cohorts: [{ value, label, isCurrent }],
  departments: [{ value, label }]
}
```

若真实 `/qt/member/list` 首次只返回若依 `TableDataInfo` 的 `rows/total/code/msg`，届次和部门元数据可分别请求后合并；该差异只存在于 API 适配层。

## 8. 推荐后端接口契约

### 8.1 届次元数据

`GET /qt/member/cohorts`

```json
{
  "code": 200,
  "msg": "操作成功",
  "data": [
    { "value": "21", "label": "第21届", "isCurrent": true },
    { "value": "20", "label": "第20届", "isCurrent": false }
  ]
}
```

当前届应由后端明确返回，前端不根据系统年份猜测。

### 8.2 成员列表

`GET /qt/member/list?pageNum=1&pageSize=20&memberCohort=21&nickName=&memberDepartment=&roleCategory=`

沿用若依 `TableDataInfo`：`{ code, msg, rows, total }`。建议每行额外返回 `memberStatus`、`roleCategory`、`joinTime` 和 `canRetain`。其中 `canRetain` 由后端基于日期、角色和历史状态计算，避免前端复制业务规则。

### 8.3 确认留任

推荐：`PUT /qt/member/{userId}/retain`

请求：

```json
{ "sourceCohort": "20" }
```

响应：

```json
{
  "code": 200,
  "msg": "留任成功，已同步至第21届",
  "data": { "sourceStatus": "retained", "targetCohort": "21" }
}
```

后端在同一事务中校验资格、更新原届记录、幂等创建下一届并同步成员。重复请求应返回既有结果，不产生重复成员。

### 8.4 年度自动任务

后端定时任务在每年 8 月 1 日执行，并使用唯一任务记录或数据库约束保证幂等：

- 管理层更新为已卸任。
- 未留任的经理层与实习生更新为已卸任。
- 已留任者的原届保持已留任，下一届记录保持在职。

前端不实现定时器，仅展示服务端结果。该约定可直接作为与后端沟通的初版说明。

## 9. Mock 行为

- 默认提供第 18–21 届数据，第 21 届为当前届。
- Mock 列表支持分页、姓名、届次、部门和角色筛选。
- 导入校验文件并返回成功摘要；不解析并持久化未知模板列。
- 删除、重置密码和留任均模拟短延迟与若依响应。
- 留任会真实修改当前内存数据并创建/更新下一届数据，使交互可连续验收。
- 页面刷新后 Mock 数据恢复初始值是可接受行为；本阶段不把业务数据写入 localStorage，避免旧结构污染测试。

## 10. 加载、异常与边界

- 初次加载和切换届次显示表格加载态，避免重复请求覆盖新结果。
- 搜索和筛选无结果时展示空状态，并保留清空条件入口。
- 网络或业务异常使用统一消息并保留当前筛选条件，允许重试。
- 删除、重置和留任提交期间禁用对应按钮，防止重复提交。
- 留任发生 409 冲突时刷新最新状态并提示“成员状态已更新”。
- 401/403 继续交由现有请求层和路由权限机制处理。
- 成员姓名、手机号和上传失败详情均进行文本渲染，不使用不受控 HTML。

## 11. 测试与验收

### 11.1 自动化测试

- API 适配：若依字段正确转换为稳定成员模型。
- Mock 查询：届次、姓名、部门、角色和分页组合筛选正确。
- 页面加载：当前届标签、表格列、状态和空状态正确。
- 权限：只读账号看不到导入、删除、重置和留任操作。
- 删除：确认、取消、成功刷新和失败保留。
- 重置密码：提交锁与成功/失败反馈。
- 留任：取消不修改；确认后原届变为已留任、下一届创建且成员为在职；重复提交不重复复制。
- 导入：文件类型、大小、提交状态、成功摘要和失败提示。

### 11.2 浏览器验收

- 使用管理员账号完成搜索、两个筛选、届次切换、删除取消、重置密码、导入校验和留任同步。
- 使用只读账号验证页面可读但写按钮全部隐藏。
- 刷新 `/members` 验证动态路由恢复且不落入 404。
- 在 1366、1440 和 1920 宽度检查工具栏、页签、表格滚动和弹窗。
- 检查浏览器控制台无未处理错误或关键警告。

### 11.3 完成标准

- Mock 模式无需后端即可走通成员管理主要流程。
- `npm run lint`、`npm run test:run` 和 `npm run build` 全部通过。
- 页面视觉与设计稿方向一致，并复用现有布局和主题。
- 切换真实模式后，若依已有接口可通过适配层接入；缺失接口有明确的后端契约文档。

## 12. 当前已知依赖

- 用户后续提供正式 Excel 名单模板，届时补齐列级校验与模板下载验收。
- 后端需确认推荐的届次、留任和成员状态字段/接口；接口路径可调整，但必须保留事务与幂等语义。
- 若若依重置密码要求前端提交新密码，需由后端产品策略明确生成方式；本阶段不在浏览器中写死通用默认密码。
