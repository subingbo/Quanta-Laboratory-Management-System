# Quanta 表格与留任弹窗微调规格

日期：2026-08-26  
状态：方案已由用户确认  
涉及模块：成员管理、招新管理

## 1. 目标与范围

本次只处理已确认的局部视觉与交互问题，不改变成员留任、招新晋级、部门数据权限或接口契约。

- 成员管理和招新管理表格的姓名列增加左侧留白。
- 成员管理的“是否留任”改用与招新管理一致的确认弹窗。
- 招新管理中的 Pass、Out 状态改为纯文字展示。
- 其他状态标签、按钮配色和业务流程保持不变。

## 2. 视觉规则

成员表格和招新表格的首列表头、首列单元格统一增加 16px 左侧内边距。该间距只应用于首列，不扩大整张表格的其他列距。

Pass 使用绿色文字，Out 使用 `#E81F1F` 红色文字。两者移除背景、胶囊圆角和额外水平内边距。待处理等其他状态标签继续沿用现有样式。

## 3. 留任确认弹窗

新增独立的成员留任确认弹窗，复用招新管理弹窗的圆角、遮罩、标题、关闭按钮和底部操作区布局。

- 标题：`成员留任确认`
- 提示：`确认 {姓名} 留任并同步到下一届名单吗？`
- 按钮：取消、确认留任
- 确认按钮使用黄色 `#FDAF32` 和白色文字。
- 提交期间显示加载态并阻止重复提交。
- 用户取消或关闭弹窗时不发起请求。
- 确认后继续调用现有留任接口；成功后刷新届次和成员列表，失败时保留弹窗并显示原有错误提示。

删除成员仍使用现有删除确认弹窗，不纳入本次改造。

## 4. 组件边界

留任弹窗作为成员管理的独立组件，只接收可见状态、成员信息和提交状态，并向父页面发送关闭及确认事件。API 调用、列表刷新和消息反馈仍由成员管理页面负责。

首列间距分别在成员表格和招新表格的局部样式中实现，避免影响系统中的其他 Element Plus 表格。Pass/Out 纯文字规则也仅作用于招新候选人表格。

## 5. 验收

- 成员管理当前届和历史届的姓名列均不再紧贴左边框。
- 招新管理看板、一面和二面表格的姓名列使用同一留白。
- 点击“是否留任”出现定制确认弹窗，取消无副作用，确认后原留任流程正常执行。
- Pass/Out 在所有招新志愿状态位置均只显示文字，没有背景椭圆。
- 相关组件测试、完整测试、代码检查和生产构建通过。
- 浏览器实测弹窗、间距和状态文字，并保存页面截图供用户复核。
