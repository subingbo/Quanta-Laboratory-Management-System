# Quanta 后台管理系统第一阶段设计规格

日期：2026-08-24  
状态：已由用户确认设计，等待书面规格复核

## 1. 背景与目标

本项目是 Quanta 社团的后台管理系统。当前工作区只有一份 Apifox 导出的 OpenAPI 文件，没有现成前端工程，后端采用若依框架但尚未部署。前端采用 Vue 3、Element Plus、JavaScript、Vite、Pinia 和 Vue Router。

第一阶段不追求一次完成所有业务页面，而是先建立稳定的工程底座，并完整实现临时登录页、后台公共布局和控制台。后续成员管理、招新管理、活动报名、工位预约、图书借阅、塔服订购和学习资料等模块直接复用该底座，避免重复建设或大面积改造。

## 2. 第一阶段范围

### 2.1 包含内容

- 创建 Vite + Vue 3 + JavaScript 工程。
- 集成 Element Plus、Pinia、Vue Router 和 Axios。
- 实现与现有设计稿一致的全局视觉变量、后台公共布局和控制台。
- 制作临时登录页，视觉沿用深蓝、橙色和浅灰配色。
- 封装登录、获取用户信息和获取动态路由的 API。
- 实现 Token 存储、登录态恢复、退出登录和登录失效处理。
- 实现动态路由转换、注入、重置以及基于动态路由的侧边栏。
- 实现全局路由守卫、白名单、访问回跳、403 和 404 页面。
- 建立页面权限和按钮权限基础设施。
- 建立本地 Mock/真实 API 双模式数据层。
- 为尚未开发的菜单提供统一“功能开发中”占位页。
- 为关键权限和路由逻辑编写自动化测试，并完成桌面端浏览器验收。

### 2.2 暂不包含

- 第一阶段不实现成员管理等完整业务页面，仅展示其动态菜单和占位页。
- 不实现手机端专用界面；桌面端窄窗口仅保证侧栏可折叠、表格或内容可滚动。
- 不在前端执行每年 8 月 1 日的自动卸任和届次结转。该能力必须由后端定时任务执行。
- 不生成用户尚未提供的名单导入模板。
- 不自行补造 OpenAPI 中缺失的正式业务接口；仅在 Mock 层模拟已确认的交互。

## 3. 技术方案

采用“双模式数据层”方案，并以若依的登录、用户信息、菜单路由和权限模型为正式对接基线。页面和 Pinia 只调用统一 API 模块，不直接读取静态数据，也不判断当前是否处于 Mock 模式。

- `VITE_USE_MOCK=true`：使用本地 Mock Adapter，返回与目标后端相同形状的数据。
- `VITE_USE_MOCK=false`：Axios 将请求发送到 `VITE_API_BASE_URL`。
- 后端上线时只配置环境变量并修正少量接口字段映射，不修改页面组件、路由守卫或状态调用方式。

不引入额外的请求拦截型 Mock 框架。Mock Adapter 保持简单、可读、可测试，并模拟 200–500ms 延迟、登录失败、401 和权限差异。

## 4. 工程结构与模块边界

建议目录职责如下：

```text
src/
  api/                 # 按业务域定义请求函数
  assets/              # 本地静态资源
  components/          # PermissionButton、StatusTag、PageCard 等通用组件
  composables/         # usePermission 等组合式逻辑
  directives/          # v-permission 按钮权限指令
  layout/              # AppLayout、Sidebar、Header、AppMain、MenuItem
  mock/                # Mock Adapter、账号、用户信息、路由和控制台数据
  router/              # 静态路由、动态路由转换、守卫和路由重置
  stores/              # user、permission、app
  styles/              # reset、变量、Element Plus 覆盖和公共页面样式
  utils/               # request、token、错误规范化等
  views/               # login、dashboard、error、placeholder
```

每个模块保持单一职责：页面负责展示与交互；Store 负责跨页面状态；API 层负责数据访问；Router 负责导航与权限；Layout 只负责后台外壳。

## 5. 登录、会话与用户状态

### 5.1 登录页面

临时登录页包含 Quanta 标识、用户名、密码、可选验证码和登录按钮。验证码是否展示由登录配置控制；本地 Mock 默认关闭验证码，但保留字段与组件能力，以匹配 OpenAPI 中的 `code` 和 `uuid`。

登录中禁用重复提交。登录失败保留用户名，不保留密码，并展示明确错误信息。

### 5.2 Mock 账号

- `admin / quanta123`：拥有全部第一阶段页面和按钮权限。
- `viewer / quanta123`：可进入控制台和只读占位页面，不拥有管理操作权限。

Mock 登录返回若依风格数据：`{ code, msg, token }`。用户信息返回 `{ code, msg, user, roles, permissions }`。

### 5.3 Token 与恢复

Token 使用独立键名 `quanta_admin_token` 存入 `localStorage`。Store 内同时保存 Token、用户、角色和权限。

Axios 请求拦截器按若依约定发送 `Authorization: Bearer <token>`。登录、验证码、用户信息、动态路由和业务错误优先遵循现有若依接口语义。

页面刷新时，如果存在 Token 但内存中没有用户信息，路由守卫先调用 `/getInfo`，再调用 `/getRouters`，最后恢复动态路由并继续原导航。任何一步失败都清理残留会话，避免半登录状态。

退出登录或收到 401 时，清理 Token、用户、权限、动态路由记录和页面缓存，再跳转登录页。若 401 来自受保护页面，登录地址携带安全的站内 `redirect` 参数，登录成功后返回原页面。

## 6. 动态路由与路由守卫

### 6.1 静态路由

静态路由只包含登录、403、404、后台根容器和必要的重定向。业务菜单均由动态路由产生。

### 6.2 动态路由契约

Mock `/getRouters` 使用若依常见字段：

```text
name, path, hidden, redirect, component, alwaysShow, meta, children
```

`meta` 至少支持 `title`、`icon`、`noCache`、`link` 和权限扩展字段。第一阶段返回当前全部设计稿菜单，包含控制台、成员管理、招新管理、宣讲会报名、精英分享会、工位预约、图书借阅、塔服订购和学习资料。

控制台映射到完整页面；其余路由映射到统一占位页面。后续开发业务模块时仅替换组件映射，不改变菜单路径和权限模型。

### 6.3 安全转换

后端的 `component` 字段只能通过前端维护的组件映射表解析。未知组件进入错误占位页并记录开发环境警告，不能直接执行任意导入路径。

动态路由注入过程设置互斥状态和已初始化标记，避免并发导航重复请求或重复 `addRoute`。系统保存每个动态路由的移除函数，退出时可完整重置。

### 6.4 守卫顺序

1. 判断目标是否在公开白名单中。
2. 检查 Token；无 Token 时跳转登录。
3. 已登录访问登录页时跳转控制台。
4. 缺少用户信息时调用 `/getInfo`。
5. 尚未初始化动态路由时调用 `/getRouters` 并注入路由。
6. 重新进入原目标路由，避免首次注入后落入 404。
7. 校验页面权限并放行；无权限进入 403；未知路径进入 404。

全局导航显示轻量加载进度，守卫无论成功或失败都正确结束进度状态。

## 7. 按钮级权限

`/getInfo` 返回字符串权限集合，例如：

```text
member:list
member:import
member:remove
member:resetPwd
member:retain
```

前端提供 `v-permission` 指令、`usePermission` 组合函数和 `PermissionButton` 组件。业务页面可按场景选择，但底层统一读取 Permission Store。

无权限按钮默认隐藏。禁用仅用于“有权限但当前业务状态不允许操作”的情况。前端权限用于界面体验，正式安全性仍由后端接口再次校验。

## 8. 页面与视觉设计

### 8.1 公共布局

- 左侧固定深蓝侧边栏，包含品牌区、分组菜单、徽标和底部用户区。
- 顶部白色栏显示当前页面标题和实时日期时间。
- 主内容区使用浅灰背景、白色卡片、轻阴影和圆角。
- 主色为设计稿中的橙色，成功、危险、信息状态使用 Element Plus 语义色并做轻量定制。
- 菜单由动态路由生成，支持多级菜单、隐藏菜单、激活态和折叠状态。

### 8.2 控制台

控制台包含欢迎横幅和四个统计卡：当届成员总数、今日新增简历、当前待生效预约、待审核塔服缴费。Mock 返回设计稿示例数据，统计 API 在后续后端契约明确后再对接。

### 8.3 桌面适配

优先覆盖 1366–1920px 常见桌面宽度，并保持设计稿的空间层级。更窄窗口自动收紧间距、折叠侧栏并让宽内容横向滚动，避免压缩表格列到不可读。

## 9. 错误、加载与空状态

- Axios 统一规范化若依风格 `code`、`msg` 和业务数据。
- 401：清理会话并返回登录页。
- 403：进入无权限页。
- 404：进入未找到页面。
- 5xx 或网络异常：显示用户可理解的错误提示，页面保留重试入口。
- 页面请求期间显示加载状态；空数组显示空状态；控制台单个统计请求失败时显示 `--`，不阻断其他卡片。
- 开发环境记录足够的诊断信息，生产界面不暴露响应堆栈或敏感请求内容。

## 10. 已记录的后续业务规则

以下要求不属于第一阶段实现范围，但后续模块必须遵守：

- 成员管理支持姓名搜索、届次页签、部门筛选和角色筛选。
- 角色分为管理层（O 字辈和 VP）、经理层、实习生。
- 导入成功显示成功提示；名单模板由用户后续提供。
- 删除成员前显示确认弹窗；重置密码成功后显示反馈。
- 点击“是否留任”先二次确认，确认后状态改为留任，并把成员同步到下一届名单；必要时自动创建下一届页签。
- 每年 8 月 1 日，管理层自动卸任；经理层和实习生若未在此前确认留任，也自动卸任。该规则由后端定时任务负责，前端只提交留任操作并展示结果。
- 招新一面和二面页面均支持编辑面评；提交后显示“已评”。已有面评可继续编辑，二面录用/淘汰流程继续保留确认和通知交互。

## 11. 测试与验收

### 11.1 自动化测试

使用 Vitest 和 Vue Test Utils 覆盖：

- 动态路由树转换和组件映射。
- 无 Token、有效 Token、失效 Token、动态路由首次加载和无权限等守卫分支。
- 刷新后的用户信息与路由恢复。
- 路由重置和退出登录。
- 按钮权限判断与指令行为。
- Mock/真实请求适配器的选择。

### 11.2 浏览器验收

- 使用两个 Mock 账号验证权限差异。
- 验证登录、刷新、退出、登录回跳和 Token 失效。
- 验证动态侧边栏、菜单激活态、折叠、占位页、403 和 404。
- 验证控制台布局在常见桌面宽度下无溢出、无遮挡。
- 验证浏览器控制台无未处理异常和关键警告。

### 11.3 交付条件

- `npm run build` 成功。
- 静态检查和自动化测试通过。
- Mock 模式无需后端即可完成全部第一阶段流程。
- 关闭 Mock 并配置 API 地址后，请求层能够转向真实后端。
- 代码结构允许后续按业务模块逐页替换占位组件。

## 12. 风险与应对

- OpenAPI 的通用响应 Schema 信息不足：以当前若依项目的标准响应和权限约定建立适配器，后端上线后再通过真实响应校准个别自定义字段。
- 招新后台接口当前不完整：第一阶段只保留路由和占位页，后续接口补齐后再实现完整业务状态机。
- 设计稿来自超宽屏：实现时以相对尺寸、最大宽度和桌面断点还原，不写死整页像素宽度。
- 前端无法可靠执行年度自动任务：正式规则明确归属后端，避免浏览器未打开时漏执行。
