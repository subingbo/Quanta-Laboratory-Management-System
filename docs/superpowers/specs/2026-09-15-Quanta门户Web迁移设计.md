# Quanta 门户 Web 迁移设计

## 目标

将 `Quanta-uniapp` 的新生端与塔员端功能完整迁移到现有 `Quanta-admin-web`，形成一个统一部署的 Vue Web 应用。应用包含新生门户、塔员门户和管理后台三种独立体验，共享认证、请求层和品牌设计系统。原有 `Quanta-uniapp` 代码完整保留，作为交互和业务参考，不删除、不覆盖，也不再作为正式上线入口。

正式产品以桌面 Web 为主要使用场景，同时保证手机浏览器的基本响应式可用性。

## 已确认的产品结构

### 路由入口

| 路径 | 用途 | 访问身份 |
| --- | --- | --- |
| `/` | Quanta 身份选择 | 公开 |
| `/login/freshman` | 新生登录，提交 `loginType=0` | 公开 |
| `/login/member` | 塔员登录，提交 `loginType=1` | 公开 |
| `/admin/login` | 管理端登录 | 公开 |
| `/freshman/*` | 新生门户 | 新生 |
| `/member/*` | 塔员门户 | 塔员 |
| `/admin/*` | 现有管理后台 | 具有对应管理权限的账号 |
| `/login` | 兼容旧链接，跳转到 `/admin/login` | 公开 |

生产应用部署在站点根路径 `/`。Nginx 对上述前端路由统一回退到 `index.html`，业务 API 路径继续转发给后端。

### 新生门户

新生门户迁移以下功能：

- 新生首页与 Quanta 介绍
- 新生功能中心
- 加入我们介绍
- 招新报名表填写、草稿保存和照片上传
- 报名状态与面试流程查看
- 宣讲会详情与报名
- 精英分享会详情与报名
- 修改密码与退出登录

### 塔员门户

塔员门户迁移以下功能：

- 塔员首页与活动动态
- 塔员功能中心
- 成员通讯录与筛选
- 个人资料
- 电子名片查看与编辑
- 账号与安全
- 我的工位、借阅和塔服订单记录
- 图书查询与借阅
- 工位查询与预约
- 塔服查看与订购
- 学习资料查看与下载
- 通知查看

### 管理后台

管理后台保留现有桌面端页面结构和左侧导航，包括控制台、访问指标、成员管理、招新管理、活动报名、工位记录、图书记录、塔服订单和学习资料管理。迁移不得将普通用户页面塞入管理后台外壳，也不得改变现有后台的主要视觉语言。

## 视觉与响应式设计

门户以已经确认的桌面端方案为主：顶部品牌导航、宽屏居中内容区、首页横幅、个人概览和多列功能卡片。颜色延续 uniapp 的橙白品牌语言：品牌橙用于主操作和强调，深灰用于主要信息区域，白色圆角卡片承载功能内容。

桌面端页面使用以下布局规则：

- 内容最大宽度统一控制，避免在超宽屏上无限拉伸。
- 首页使用横幅与个人概览双栏，功能区使用三至四列卡片。
- 报名、名片和安全设置等表单使用信息区与表单区双栏。
- 进度、服务记录、图书、工位和订单使用适合桌面的表格、时间线或网格。

手机端保留可用性但不复刻小程序底部导航：顶部导航折叠为菜单，双栏和多栏回落为单列，操作按钮保持足够触控面积，表格转换为卡片或允许安全横向滚动。

## 前端架构

### 布局边界

应用新增四类布局单元：

- 公共入口布局：身份选择和三类登录页。
- 新生门户布局：新生顶部导航、用户状态和内容出口。
- 塔员门户布局：塔员顶部导航、个人入口和内容出口。
- 管理后台布局：复用现有 `AppLayout`。

每个布局只负责导航、身份展示和内容容器，不包含具体业务数据。业务页面通过 Vue Router 子路由挂载，避免形成单个超大页面组件。

### 路由与身份守卫

认证成功后统一请求 `/getInfo` 获取用户、角色和权限。前端保存当前登录入口类型，并将其与后端用户信息共同用于路由判定：

- 新生只能访问 `/freshman/*`。
- 塔员可以访问 `/member/*`；若账号同时具备管理权限，可显式进入 `/admin/*`。
- 管理页面继续按 `permissions` 做页面和按钮级校验。
- 身份不匹配时跳转到相应门户首页或 403 页面，不静默放行。
- 401 清理登录状态并回到对应身份登录页，同时保留安全的站内重定向。

### API 分层

门户 API 放在独立目录中，按认证、新生招新、活动、成员、资料、图书、工位、塔服和个人账户拆分。每个模块将若依响应转换成稳定的页面视图模型，页面不直接依赖后端字段名。

接口调用遵循以下原则：

- 登录、用户信息、活动、招新、成员、学习资料、通知、图书、工位、订单和密码修改优先连接真实后端。
- 后端已经迁移的业务接口统一使用 `/qt/*` 路径。
- 普通网络错误、401、403、参数错误和 500 不自动回退 Mock。
- 写操作只有在真实后端返回业务成功后才向用户显示成功。
- 上传使用浏览器 `FormData`，照片和文件校验与后端限制保持一致。

## 数据流

登录数据流：

1. 用户在 `/` 选择身份。
2. 登录页提交用户名、密码和对应 `loginType`。
3. 前端保存 Token，随后调用 `/getInfo`。
4. 身份守卫验证入口类型、角色和权限。
5. 用户进入对应门户；身份不匹配时拒绝进入并给出明确提示。

页面数据流：

1. 页面进入后调用对应 API 模块。
2. API 模块规范化若依响应并映射为视图模型。
3. 页面展示加载、成功、空状态或错误状态。
4. 写操作完成后重新获取服务端数据，不仅修改本地界面状态。

报名表草稿保存在浏览器本地存储中；正式提交成功后清理草稿。电子名片在后端接口缺失期间也保存在本地存储中，并在页面上明确这是当前浏览器中的资料。

## 真实接口与 Mock 边界

迁移时创建 `docs/Quanta门户Web端接口Mock清单.md`，逐项记录路径、缺失原因、临时行为、取消条件和最近复测日期。

当前已确认允许保留的本地数据只有：

- 电子名片：后端没有对应增删改查接口，暂使用浏览器本地存储。
- 首页品牌轮播：属于展示素材，使用项目静态资源，不伪装成后端业务数据。

工位预约当前 uniapp 页面虽然使用本地 Mock，但最新后端已经提供 `/qt/workstation` 与 `/qt/reservation`，Web 迁移必须优先完成真实接口适配。若实际联调发现契约缺失，才能将具体接口加入门户 Web Mock 清单。

## 错误处理与用户反馈

- 首次加载显示骨架或明确的加载状态。
- 空数据使用业务化空状态，不显示空白页面。
- 网络失败保留当前页面并提供重新加载按钮。
- 401 清理失效会话并跳转到对应登录页。
- 403 显示无权限说明，不伪装成数据为空。
- 表单字段错误就近显示；后端业务消息经过安全处理后展示。
- 有未保存表单时，站内离开页面前给出提示。
- 重复提交按钮在请求期间禁用。
- 上传前校验文件类型和大小，后端拒绝时显示真实原因。

## 测试与验收

自动化测试至少覆盖：

- 三种登录入口提交正确 `loginType`。
- 新生、塔员和管理路由之间的身份隔离。
- 401、403 和安全重定向行为。
- 各 API 模块的请求路径、参数和响应映射。
- 报名草稿、电子名片本地存储和清理规则。
- 表单校验、重复提交保护、空状态和错误重试。
- 桌面导航与手机折叠菜单的基础交互。
- 生产构建使用站点根路径并能直接访问深层路由。

人工浏览器验收按身份逐页执行：

- 新生：登录、首页、招新报名、进度、两类活动报名、改密和退出。
- 塔员：登录、首页、通讯录、资料、名片、安全、服务记录、图书、工位、塔服、资料和通知。
- 管理：确认现有后台全部页面与访问指标页面未回归。
- 响应式：桌面宽屏为主要验收；手机宽度验证导航、表单和关键操作可用。

## 迁移顺序

1. 建立根路径部署、三身份路由和布局骨架。
2. 迁移共享认证、请求层、设计变量和公共组件。
3. 完成新生门户的页面与真实接口。
4. 完成塔员门户的资料、通讯录和内容功能。
5. 完成塔员自助服务：图书、工位、塔服和服务记录。
6. 补齐明确的本地数据清单与接口联调记录。
7. 执行三身份回归、生产构建和浏览器逐页验收。

每个阶段都必须保持管理后台可构建、可登录、可使用，避免在整个迁移结束前留下不可运行的主分支状态。
