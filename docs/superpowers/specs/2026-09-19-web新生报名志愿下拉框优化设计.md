# Web 新生报名志愿下拉框优化设计

## 目标

优化新生端报名表中“第一志愿”和“第二志愿”的选择体验，替换浏览器原生下拉菜单，使其与 Quanta 门户的橙黑视觉一致，同时保持现有表单数据、校验规则、提交接口和桌面布局不变。

## 范围

- 仅修改 Web 新生端报名表的第一志愿、第二志愿选择控件。
- 性别选择框和其他表单控件不在本次范围内。
- 不修改部门枚举、表单字段名、提交数据或后端接口。
- 保持桌面端双列布局，并兼容现有 H5 单列布局。

## 组件设计

新增轻量的 `RecruitmentDepartmentSelect` 组件，通过 `v-model` 接收部门编码，通过 `options` 接收现有 `recruitmentDepartments`。

组件包含：

- 与现有输入框等高的触发按钮；
- 自定义圆角浮层菜单；
- 当前选中项的橙色高亮和勾选标记；
- 未选择时显示“请选择”；
- 第一、第二志愿继续使用同一组件，但维护各自独立状态。

## 交互与无障碍

- 点击触发按钮展开或收起菜单。
- 点击选项后更新 `v-model` 并关闭菜单。
- 点击组件外部或按 `Escape` 关闭菜单。
- 支持方向键移动高亮项，按 `Enter` 或空格确认。
- 使用 `aria-expanded`、`aria-controls`、`role="listbox"` 和 `role="option"` 表达控件状态。
- 表单校验失败时沿用现有红色边框、提示文字和聚焦逻辑。

## 视觉规范

- 默认状态使用白色背景、浅灰边框和 13px 圆角。
- 展开或聚焦时使用 Quanta 橙色边框及浅橙色聚焦光晕。
- 下拉浮层使用白色背景、16px 圆角、轻阴影和适当间距。
- 选项悬停/键盘高亮使用浅橙背景；已选项使用橙色文字与勾选图标。
- 浮层宽度跟随控件，移动端不超出视口。

## 数据流与错误处理

- 组件仅传递已有部门编码，不转换或新增业务字段。
- 第一志愿和第二志愿相同的校验仍由现有 `validateApplication` 负责。
- 无选项或异常值时回退显示“请选择”，不影响表单其他字段。

## 验证

- 单元测试覆盖展开、选择、键盘操作、外部关闭和 `v-model` 更新。
- 验证第一、第二志愿相同仍会触发现有校验。
- 执行相关 Vitest、ESLint 和生产构建。
- 在桌面宽度与 375px/430px 移动端宽度检查浮层定位、无横向溢出以及原有布局不变。
