# Web 管理端招新体验修复设计

## 目标

只修改 `Quanta-admin-web`，修复管理端导航提示、简历详情、面评入口、招新筛选和身份返回入口；不修改后端接口、数据库或 UniApp。

## 设计

- 移除侧栏基于路由静态 `meta.badge` 的红点展示。在没有未读消息接口之前，不显示无法代表真实状态的数字。
- 简历弹窗统一读取前端标准化后的 `choices`，按 `choiceOrder` 显示第一、第二志愿；邮箱和联系方式兼容现有字段，缺失时显示“暂无”。
- 保留现有 `FeedbackDialog` 和保存接口，解除仅二面部长可编辑的前端限制：一面、二面只要用户拥有面评权限且存在可评志愿，就显示“编辑面评”。管理角色原有“查看面评”和录用操作继续保留。
- 一面、二面列表上方加入部门选择及学号/姓名搜索。筛选只作用于当前已加载的前端列表，不向后端增加参数；部门匹配候选人的任一志愿，关键字匹配学号或姓名。提供搜索、重置和结果数量提示。
- 管理端页头增加“返回选择身份”，跳转到 `/`。身份切换时沿用现有路由守卫的跨身份会话清理逻辑。

## 约束与降级

- 后端未返回邮箱时只能显示“暂无”。
- 前端筛选范围为当前接口一次加载的最多 50 条记录，不改变服务端分页和导出行为。
- 不提交本轮已有的新生端未提交修改，不修改后端。

## 验证

- 为简历字段、面评操作、筛选逻辑、侧栏红点和身份返回按钮补充组件测试。
- 运行 Web 全量单元测试、ESLint 和生产构建。
