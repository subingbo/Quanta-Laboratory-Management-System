# Web 招新管理分页设计

## 目标

为管理后台招新管理的一面、二面名单增加分页，避免候选人过多时表格过长，并消除当前固定只读取前 50 条数据的问题。

## 页面行为

- 一面、二面列表底部显示分页器。
- 默认每页 10 条，可切换 10、20、50 条。
- 显示总人数、页码、上一页和下一页。
- 一面和二面分别记住当前页；切换分页大小或应用筛选时回到第一页。
- 数据变更后刷新当前页；若当前页因删除或筛选变为空，则回到最后一个有效页。
- 招聘看板不显示分页器。

## 数据策略

### 普通浏览

直接使用现有 `/qt/interview/admin/applications` 的 `pageNum`、`pageSize`，由后端返回当前页 `rows` 和总数 `total`。部门筛选通过现有 `department` 参数交给后端。

### 学号/姓名搜索

后端当前仅支持姓名和部门条件，没有学号查询条件。为保持现有“学号或姓名”搜索能力且不改后端：

1. 搜索时按每批 100 条请求符合轮次、部门范围的候选人；
2. 根据首次响应的 `total` 继续读取剩余页面；
3. 在前端对 `studentNo`、`name`、`realName` 做不区分大小写匹配；
4. 对过滤后的结果进行本地分页。

清空关键词后立即恢复普通后端分页。该策略只在用户主动搜索时加载完整候选集合，不增加日常浏览成本。

## 组件边界

- `RecruitmentPagination.vue` 只负责分页展示与页码/每页条数事件。
- `recruitment/index.vue` 负责一面、二面分页状态、请求模式和筛选重置。
- `CandidateTable.vue` 继续只渲染传入的当前页数据，不修改业务按钮和权限逻辑。
- `api/recruitment.js` 沿用现有 `getRecruitmentApplications(query)`，不新增或修改后端接口。

## 错误与并发

- 沿用现有请求序号，忽略切换页签或快速翻页产生的过期响应。
- 搜索批量请求任一页失败时显示现有“招新名单加载失败”，不展示不完整结果。
- 加载期间禁用分页操作，避免重复请求。

## 验证

- 一面、二面均能切页和切换每页条数。
- 部门筛选与清空筛选会回到第一页。
- 学号、姓名搜索覆盖 50 条以后的候选人，并能对结果分页。
- 一面、二面切换后恢复各自页码。
- 分页不改变阅览简历、面评、评分、Pass/Out、发邮件等逻辑。
- 桌面端布局正常；窄屏下分页器可换行且不产生横向溢出。
