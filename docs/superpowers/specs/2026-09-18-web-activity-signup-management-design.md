# Web 管理端活动报名合并设计

## 目标

在 Web 后台管理系统中，将旧的“宣讲会报名”和“精英分享会”名单入口合并为“活动报名”，放入“塔员端”导航分组。所有能够进入后台管理系统的管理账号均可查看完整活动报名数据；新生账号继续只能读取自己的报名记录。

## 导航与页面

- 移除后台导航中的“宣讲会报名”和“精英分享会”独立入口。
- 在“塔员端”分组新增“活动报名”入口。
- 页面顶部提供活动名称、活动类型和活动状态筛选。
- 活动列表展示活动名称、类型、时间、地点、容量、已报名人数和“查看名单”操作。
- 点击“查看名单”后展示报名人的姓名、学号、专业、联系方式、报名时间和报名状态。
- 页面提供当前筛选结果的名单导出功能。
- 本次仅提供查询与导出，不提供审核、修改或删除报名记录。

## 数据流

1. 页面通过活动列表接口加载活动，并传递筛选条件。
2. 选中活动后，通过通用活动报名详情接口按 `activityId` 查询报名名单。
3. 前端统一映射活动和报名状态，展示加载中、空数据和接口失败状态。
4. 导出使用当前已加载、已筛选的报名名单生成文件。

## 权限边界

- `admin`、`ceo`、`qt_mgmt`、`qt_manager` 等后台管理身份可以查询所有人的报名数据。
- 新生身份访问原有报名详情接口时仍被后端限定为本人数据。
- 前端入口对后台登录账号可见，但后端仍负责最终数据权限校验，不能仅依赖菜单隐藏。
- 新页面不向普通后台账号开放报名修改、删除或状态审批能力。

## 兼容处理

- 旧的两个名单页面不再出现在导航中，避免重复入口。
- 通用活动报名组件加入前端动态路由组件映射，保证后端菜单能够正常解析。
- 数据库菜单补丁负责新增合并入口、授予后台管理角色查询权限并隐藏旧入口。

## 验证

- 验证所有后台管理角色都能看到“活动报名”入口并查看完整名单。
- 验证新生账号无法查询其他用户的报名记录。
- 验证筛选、空列表、接口错误和名单导出。
- 执行前端单元测试、代码检查和生产构建；执行相关后端权限测试。
