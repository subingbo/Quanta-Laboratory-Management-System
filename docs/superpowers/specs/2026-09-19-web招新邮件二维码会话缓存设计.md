# Web 招新邮件二维码会话缓存设计

## 目标

管理端连续发送录用邮件时，避免为同一部门反复从本地选择同一张群二维码。仅调整 Web 前端，不修改后端接口和邮件业务规则。

## 交互

- 第一次为某部门发送录用邮件时，仍需选择 JPG、JPEG 或 PNG 图片，大小不超过 5 MB。
- 图片校验通过后，前端在当前页面会话内按部门保存该 `File` 对象。
- 再次向同部门候选人发送邮件时，弹窗自动选中并预览缓存图片。
- 用户可以在弹窗中“更换图片”或“清除缓存”。
- 刷新页面、关闭页面或退出登录后缓存自然失效，不写入 localStorage、IndexedDB 或服务器。
- 淘汰邮件不展示也不使用二维码。

## 部门与权限

- 缓存键使用候选人的最终录用部门标识，严禁跨部门复用。
- 普通部门账号只能处理自己有权发送的部门邮件；管理员仍可处理全部部门，但缓存也按部门隔离。
- 权限和最终部门继续以后端返回结果及现有发送权限为准，前端缓存不扩大权限。

## 数据流

1. 打开发送弹窗并加载后端邮件预览。
2. 根据最终录用部门查找当前页面内的缓存图片。
3. 命中时自动带入；未命中时等待用户选择。
4. 用户选择或更换图片后更新对应部门缓存。
5. 发送时仍调用现有 multipart 接口并上传真实文件，不传缓存路径或新增字段。
6. 发送失败保留缓存，方便重试；文件失效或校验失败时清除该部门缓存并要求重新选择。

## 组件边界

- 招新页面持有按部门划分的会话缓存，确保多次打开弹窗时数据仍在。
- `NoticeDialog` 只负责展示预览、选择/更换/清除文件、校验并提交选中的文件。
- 现有邮件模板、单次发送、结果完整性和权限逻辑保持不变。

## 测试

- 首次发送必须选择二维码。
- 同部门第二次打开弹窗自动复用缓存文件。
- 不同部门之间不复用。
- 更换图片会更新缓存，清除后重新要求选择。
- 淘汰邮件不读取缓存。
- 发送失败后仍能复用，刷新页面后不再保留。
