# 新生 Web 注册与邮箱管理设计

## 目标与范围

为 Web 新生端增加真实账号注册和邮箱修改能力。只修改 `/login/freshman` 与 `/freshman/security`；塔员登录、塔员安全页和管理端保持不变。

## 新生登录与注册

- `/login/freshman` 增加“登录 / 注册”切换。
- 登录模式把字段文案从“用户名”改为“学号”，占位提示为“请输入学号”；请求字段仍为后端兼容的 `username`。
- 注册模式只收集：学号、邮箱、密码、确认密码，以及验证码（后端启用时）。
- 学号就是用户名。前后端都按 `^20\d{9}$` 校验，即 `20xx` 入学年份加 7 位数字，总计 11 位，例如 `20241003193`。
- 邮箱必填，前端使用常规邮箱格式校验，后端再次校验格式和唯一性。
- 密码沿用系统 5–20 位限制；确认密码只在前端校验，不发送到后端。
- 注册成功后切回登录模式并自动带入学号，不自动登录。

## 后端注册契约

- 复用匿名 `POST /register`，不新增重复注册控制器。
- 服务端忽略客户端传入的独立用户名，强制 `username = studentNo`。
- `RegisterBody` 增加 `email`。
- 注册服务去掉班级必填要求，校验学号格式、学号唯一、用户名唯一、邮箱格式和邮箱唯一，并写入 `sys_user.email`。
- 自助注册始终写入 `is_quanta_member = '0'`；塔员仍不能自助注册。
- 保留验证码开关和现有 IP 注册限流。

## 新生修改邮箱

- `/freshman/security` 在修改密码下方增加“修改邮箱”卡片，展示当前邮箱并输入新邮箱。
- 新增 `PUT /system/user/profile/updateEmail`，请求体为 `{ email }`。
- 接口仅允许 `isQuantaMember != '1'` 的当前用户调用；塔员和管理员不能通过此入口修改邮箱。
- 后端校验邮箱格式、唯一性，只更新当前用户邮箱并刷新登录缓存，不覆盖昵称、手机号或性别。
- 前端通过 `/getInfo` 读取当前邮箱；成功后刷新用户信息。

## 错误处理与安全

- 学号、邮箱、密码格式错误显示在对应字段下。
- 学号或邮箱重复、注册关闭、限流、验证码错误直接展示后端真实信息。
- 请求失败不显示成功、不写入本地假数据。
- 注册和邮箱修改按钮在请求期间禁用，防止重复提交。

## 测试与验收

- Web：API 请求、学号/邮箱/确认密码校验、注册成功切回登录、仅新生显示邮箱卡片。
- 后端：学号格式、学号即用户名、邮箱唯一、强制新生身份、塔员禁止调用邮箱接口。
- 回归：新生登录、塔员登录、管理登录、修改密码、全量测试、Lint、构建和浏览器真实后端冒烟。
