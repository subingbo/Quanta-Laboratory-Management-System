# Web 端 RUM 与 Trace ID 接入设计

## 目标

为 Quanta Web 项目的所有统一网络请求增加可追踪的请求标识，并为后续接入阿里云 ARMS 用户体验监控准备清晰的操作手册和配置边界。

本次只直接启用 Trace ID。ARMS RUM SDK 必须在取得阿里云控制台生成的上报 `endpoint` 后才启用，避免生产环境加载无效探针。

## Trace ID 规则

- 请求头名称统一为 `X-Trace-Id`。
- 每次请求生成一个新的 Trace ID，不按页面或登录会话复用。
- 优先使用浏览器 `crypto.randomUUID()`，移除连字符后得到 32 位十六进制字符串。
- 浏览器不支持 `randomUUID()` 时，使用 `crypto.getRandomValues()` 生成 16 字节随机数；测试或极端旧环境再使用时间戳与随机数组合的兼容值。
- 调用方显式传入 `X-Trace-Id` 时保留原值，不覆盖。
- Mock 请求同样携带 Trace ID，保证本地开发行为与线上一致。
- 请求失败时，将请求使用的 Trace ID 写入错误对象的 `traceId` 字段，供错误提示和后续 RUM 自定义属性使用。

## 代码边界

- 新建独立的 Trace ID 工具，负责生成、读取和补全请求头。
- 统一请求模块负责为真实请求与 Mock 请求应用 Trace ID，并在异常标准化时保留该值。
- 不修改任何后端代码。
- 不在控制台打印 Token、请求体、简历数据或用户密码。

## 阿里云 RUM 手册

在 `docs` 目录生成一份中文操作手册，内容包括：

1. 在阿里云 ARMS 控制台创建 Web & H5 应用并取得 `endpoint`。
2. 需要提供给前端的配置项及生产环境变量建议。
3. 后端读取 `X-Trace-Id`、写入日志上下文、回传响应头的建议。
4. 跨域情况下允许 `X-Trace-Id` 请求头并暴露响应头的 CORS 配置要求。
5. RUM 隐私过滤、采样、版本号、SPA 路由和验收检查。
6. 明确禁止提交账号密钥、AccessKey、Token 或其他服务端凭据。

## 测试与验收

- Trace ID 为 32 位十六进制字符串。
- 连续生成的请求标识不同。
- 已有请求标识不会被覆盖。
- 真实请求配置和 Mock 请求配置均包含 `X-Trace-Id`。
- 网络错误和业务错误均能读取 `error.traceId`。
- Web 全量单元测试、构建和代码检查通过，且不新增警告。

## 后续 RUM 接入

收到 ARMS `endpoint` 后，通过环境变量初始化 `@arms/rum-browser`，设置 SPA 模式、环境、版本和采样率。RUM 上报前必须过滤敏感字段，并把发生错误或慢请求时对应的 Trace ID 作为自定义属性关联。
