# Quanta Admin Web 登录页与真实后端接入设计

日期：2026-09-13  
适用项目：`Quanta-admin-web`

## 目标

1. 修复开发环境仍默认使用 Mock、页面展示错误测试账号导致真实后端无法登录的问题。
2. 使用 Quanta 社团 Logo 重做登录页，并与后台现有深蓝、橙色视觉体系保持一致。
3. 将 Web 管理端默认接入真实后端；仅对已经确认缺失或存在阻塞问题的接口显式使用 Mock。
4. 建立带 Web 端标识的 Mock 接口清单，便于后续逐项切回真实接口。

## 已确认现状

- `Quanta-admin-web/.env.development` 当前为 `VITE_USE_MOCK=true`，因此常规开发启动不会调用真实后端。
- 前端页面展示的 `admin / quanta123`、`viewer / quanta123` 属于 Mock 账号。
- 后端 `http://127.0.0.1:8080/captchaImage` 已正常响应，且当前未启用验证码。
- 实测 `admin / quanta123` 返回“用户不存在/密码错误”；`admin / admin123` 登录成功并返回 token。
- 根项目文档和数据库种子数据约定的真实测试账号密码均为 `admin123`。

## 方案选择

采用“真实接口优先、显式 Mock 白名单”方案。

不采用运行时遇错即自动回退 Mock。401、403、参数错误和 500 等错误必须暴露出来，否则会掩盖权限、契约或后端实现问题。也不采用整模块真假切换，因为同一模块内可能只有个别接口未完成。

## 登录页设计

### 视觉

- 使用用户提供的 Quanta Logo 作为正式品牌资产，保存到 Web 项目的静态资源目录。
- 桌面端保留左右分栏：左侧为深蓝黑品牌主视觉，使用橙色柔光、细网格或轨迹装饰；右侧为浅色、轻玻璃质感的登录卡片。
- 品牌色沿用后台现有变量：橙色主色、深蓝侧栏、浅灰页面背景和深色正文。
- Logo 不改变图形本体，仅通过圆角容器、尺寸、阴影和背景融合到页面中。
- 移动端折叠品牌大区，保留紧凑 Logo、标题、表单和连接状态。

### 内容与交互

- 保留用户名、密码、可选验证码、显示密码和提交 loading。
- 开发环境账号提示改为真实账号 `admin / admin123`，不再展示不存在于真实后端的账号。
- 页面显示当前数据源状态：真实后端或 Mock；此信息仅用于开发环境。
- 登录错误继续展示后端返回的明确消息；登录失败后清空密码和验证码并刷新验证码。
- 登录认证永远使用真实接口，不进入 Mock 白名单。

## 真实后端与 Mock 路由设计

### 配置原则

- 开发环境默认配置为真实后端：`VITE_USE_MOCK=false`，API 根地址为 `http://127.0.0.1:8080`。
- 保留全量 Mock 能力供离线开发或测试使用，但不作为日常默认值。
- 增加按“请求方法 + 路径”匹配的 Mock 白名单。请求命中白名单时直接交给现有 `mockRequest`，其余请求发送到真实后端。
- 白名单为显式静态配置，不根据运行时错误自动增长。

### 请求流程

1. 请求进入统一请求层。
2. 若全量 Mock 开关开启，使用现有 Mock。
3. 否则检查 Web Mock 白名单；命中则使用 Mock，并在开发控制台给出清晰提示。
4. 未命中则请求真实后端。
5. 真实后端返回 401、403、404、500 或业务错误时正常抛出，不自动回退。

### 安全边界

- `/login`、`/getInfo`、`/getRouters`、`/logout` 不允许加入 Mock 白名单。
- 写操作不能因真实请求失败而自动改为 Mock 成功，避免用户误以为数据已保存。
- 如某个写接口确实尚未实现，必须由清单显式记录并切换，页面同时应能让开发者识别当前使用了 Mock。

## Web 端 Mock 接口清单

实现阶段建立独立文件：

`docs/Quanta管理端Web接口Mock清单.md`

文件名明确包含 `web`，内容至少记录：

- 业务模块；
- HTTP 方法与路径；
- 当前问题或缺失行为；
- 使用 Mock 的原因；
- 前端临时行为；
- 验证真实接口所需条件；
- 状态（Mock、待复测、已切真实）；
- 最近确认日期。

只有经过实际联调确认的问题接口才进入清单。真实接口修复并验证通过后，从运行时白名单移除，并在清单中保留“已切真实”的历史记录。

## 文件与组件边界

- 登录页 Vue 文件负责表单状态、验证码和登录交互。
- 登录页 CSS 文件负责响应式布局与品牌视觉，不引入额外 UI 框架。
- Logo 作为独立静态资源引用，避免把大段 Base64 写入组件。
- 请求工具负责真实请求和 Mock 路由选择。
- Mock 白名单配置独立成小模块，仅描述匹配规则，不包含业务实现。
- Mock 接口问题清单放在根 `docs` 目录，与代码配置保持一一对应。

## 错误处理

- 网络不可达：提示网络连接异常，不回退 Mock。
- 认证和权限失败：保留 401/403 处理流程，不回退 Mock。
- 后端业务错误：展示后端 `msg`，不回退 Mock。
- 白名单 Mock 缺少对应处理器：明确报出 Mock 接口不存在，避免请求静默成功。
- Logo 加载失败：页面文字品牌仍可识别，布局不坍塌。

## 验证方案

- 单元测试：数据源判定、请求白名单匹配、认证接口禁止 Mock、错误不自动回退。
- 登录页测试：真实账号提示、连接状态、表单校验、验证码条件渲染和登录错误。
- 构建检查：运行测试、Lint 和生产构建。
- 联调冒烟：使用 `admin / admin123` 登录，依次验证 `/getInfo`、`/getRouters` 和主要业务页面。
- 接口盘点：逐页触发查询和关键操作，将确认缺失或异常的接口写入 Web Mock 清单并加入白名单。
- 视觉检查：桌面端和移动端检查无溢出、Logo 清晰、对比度与焦点态正常。

## 完成标准

- 常规开发启动默认连接真实后端，真实账号可登录并进入后台。
- 登录页使用正式 Quanta Logo，视觉上与后台一致且适配移动端。
- 未完成接口按显式白名单继续使用 Mock，真实错误不会被自动掩盖。
- `docs/Quanta管理端Web接口Mock清单.md` 与实际白名单一致，并明确标识为 Web 端。
