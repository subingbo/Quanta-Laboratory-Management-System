# 老生端安全导航栏设计

## 目标

统一修复老生端微信小程序页面的顶部适配问题：右上角业务图标不得与微信胶囊按钮重叠，页面标题不得被刘海或灵动岛遮挡，并保持现有页面的视觉风格与业务行为不变。

## 范围

本次只修改老生端页面：

- 首页、通讯录、功能页的品牌型顶部栏。
- 塔服订购、个人名片查看、个人名片编辑、账号安全、我的服务、图书借阅、工位预约的详情型顶部栏。
- 个人中心没有页面标题或右上角业务按钮，其用户信息区域已有顶部安全区留白，本次不改。
- 新生端当前真机表现正常，且没有同样的右上角业务按钮冲突，本次不改。

## 方案选择

采用统一组件方案，而不是逐页增加固定边距。

1. **统一安全导航组件（采用）**：根据运行设备窗口信息和微信胶囊位置计算布局，一处维护，覆盖不同 iPhone、安卓挖孔屏和微信胶囊尺寸。
2. **逐页写死偏移量（不采用）**：改动少，但只能适配当前设备，换机型仍可能重叠。
3. **恢复微信原生导航栏（不采用）**：适配稳定，但会破坏现有品牌型顶部栏和页面视觉一致性。

## 架构

### 导航尺寸计算模块

新增纯函数模块，接收窗口宽度、状态栏高度、安全区和胶囊矩形，输出：

- 顶部安全占位高度。
- 导航内容行高度。
- 导航栏总高度。
- 微信胶囊占用的右侧宽度。
- 业务操作区与胶囊之间的间距。

微信小程序运行时使用 `uni.getWindowInfo()` 与 `uni.getMenuButtonBoundingClientRect()`。当胶囊 API 在 H5、测试或异常环境不可用时，使用保守的默认导航高度和右侧边距，页面仍能正常渲染。

所有尺寸计算使用 `px`，避免把系统返回的逻辑像素与 `rpx` 混算。计算结果同步生成，减少页面首次渲染时的跳动。

### 统一导航组件

新增 `MemberSafeHeader`，支持两种模式：

- `brand`：左侧显示 `Quanta`，右侧操作插槽放搜索、通知或喇叭。右侧操作区结束位置固定在微信胶囊左侧，并保留视觉间距。
- `detail`：左侧返回按钮，标题在安全导航内容区内居中。标题区域限制最大宽度，不能进入返回按钮区或微信胶囊区。

组件负责顶部安全区、动态高度、胶囊避让、标题定位和基础字号。页面继续负责自身背景、正文间距以及点击行为。

## 页面迁移

首页、通讯录和功能页移除原有 `.header` 的固定顶部定位，改用 `MemberSafeHeader` 的 `brand` 模式，并把现有图标放入操作插槽。功能页喇叭与微信胶囊保持至少约 `20rpx` 的视觉间距。

详情页移除各自的 `.top-bar`、占位元素和写死的顶部 `padding`，改用 `detail` 模式。正文从统一导航栏之后开始，原有标题字号可通过组件属性区分常规与强调样式，但垂直位置统一受安全区控制。

## 异常与兼容处理

- `getWindowInfo` 缺少字段时使用安全默认值。
- 胶囊矩形缺失、宽高无效或超出窗口时，不使用异常数据，回退到默认右侧保留区域。
- 安全区和状态栏高度同时存在时采用更保守的顶部值，确保内容不进入遮挡区域。
- 页面业务按钮、返回逻辑、滚动容器和底部导航保持不变。

## 测试与验收

- 为尺寸计算纯函数覆盖普通 iPhone、灵动岛 iPhone、安卓和无胶囊数据回退场景。
- 静态布局测试确认所有范围内老生端页面都使用统一组件，不再依赖原有写死顶部导航间距。
- 运行现有 Vitest 全量测试。
- 运行 `npm run dev:mp-weixin`，检查编译产物包含统一导航组件和动态样式。
- 微信开发者工具分别使用普通 iPhone 与灵动岛机型模拟：标题位于遮挡区下方；搜索、通知和喇叭位于胶囊左侧；各页面正文起点无异常跳动。

## 不在本次范围内

- 不调整新生端页面。
- 不重做导航栏视觉设计。
- 不实现通知、搜索或喇叭按钮尚未开放的业务功能。
- 不修改底部导航栏。
