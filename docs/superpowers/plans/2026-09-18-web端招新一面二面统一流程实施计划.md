# Web端招新一面二面统一流程 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 将 Web 管理端招新改造成按志愿轨道处理的一面面评、二面评分、录用决定和单次邮件通知闭环。

**Architecture:** 继续复用 `qt_interview_result` 的“报名 + 轮次 + 部门”唯一记录承载一面/二面状态及二面唯一分数；后端集中计算晋级轨道和最终录用部门，前端只渲染标准化轨道模型。录用决定与邮件发送彻底拆分，邮件预览和发送均由后端根据最终结果生成固定模板，并以幂等状态阻止重复发送。

**Tech Stack:** Vue 3、Element Plus、Pinia、Vitest、Spring Boot 4、Spring Security、MyBatis、MySQL、JUnit 5、Mockito、JavaMailSender

**Spec:** `docs/superpowers/specs/2026-09-18-web端招新一面二面统一流程设计.md`

> **范围更新（2026-09-18）：** 用户明确本轮只由前端开发负责，因此执行时不修改 `ruoyi-*` 或 `sql/`。后端相关任务仅作为接口契约说明保留；前端按 Task 6-9 实现，并把未联调的新接口登记到 `docs/Quanta管理端Web接口Mock清单.md`，不对写请求做自动 Mock 成功回退。

## Global Constraints

- 只修改 Web 管理端招新及其后端契约，不修改 UniApp 页面。
- 两个志愿一面都 `PASS` 时，两条志愿都进入二面。
- 结果写入只允许 `PENDING`、`PASS`、`OUT`；读取历史 `FAIL` 时按 `OUT` 展示。
- 一面只有文字面评；二面只有每个“候选人 + 部门”唯一的 0 至 100 整数分数。
- 普通部门账号只能读写本部门面评和分数；结果决定与邮件发送必须由后端权限控制。
- 每位候选人最终只发送一封结果邮件；双 `PASS` 优先第一志愿。
- 录用邮件必须携带 JPG、JPEG 或 PNG 群二维码，最大 5 MB；淘汰邮件不要求附件。
- 写接口失败不得自动回退 Mock 或伪造成功。
