# Web 招新邮件二维码会话缓存 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 在不修改后端接口的前提下，让管理端按录用部门复用当前页面会话中最近选择的邮件二维码。

**Architecture:** 使用页面内 `Map` 保存“部门标识 → File”，由招新页面控制缓存生命周期和部门隔离；邮件弹窗接收缓存文件并提供预览、更换、清除。发送接口继续接收原有 multipart 文件。

**Tech Stack:** Vue 3、Element Plus、Vitest、Vue Test Utils

**Spec:** `docs/superpowers/specs/2026-09-19-web招新邮件二维码会话缓存设计.md`

## Global Constraints

- 只修改 `Quanta-admin-web`，不修改后端接口。
- 仅缓存于当前页面内存，刷新、关闭页面或退出后失效。
- JPG、JPEG、PNG，最大 5 MB。
- 按最终录用部门隔离，淘汰邮件不使用二维码。
- 发送失败保留缓存，现有模板、权限、幂等和 multipart 请求保持不变。

- [x] **Step 3: 实现最小缓存对象**

```js
export function createDepartmentFileCache() {
  const files = new Map()
  const keyOf = (department) => String(department || '').trim().toUpperCase()
  return {
    get(department) { return files.get(keyOf(department)) || null },
    set(department, file) { const key = keyOf(department); if (key && file) files.set(key, file) },
    clear(department) { const key = keyOf(department); if (key) files.delete(key) },
  }
}
```

- [x] **Step 4: 运行测试确认通过**

Run: `npm run test:run -- src/views/recruitment/__tests__/department-file-cache.test.js`
