## 1. 前端同学必做（改 `Quanta-uniapp`，不要改管理端）

实现细节、字段名、参考代码：**全文跟 [简历投递数据打通待办.md](简历投递数据打通待办.md)**。下面是开工顺序和本轮边界。

### 1.1 投递打通（主体）

现状：`src/pages/freshman/join-us/submit.vue` 的 `handleSubmit` 仍 `saveApplication` + `/* TODO: 后端上线后替换为真实投递接口 */`，零网络请求。

- 新建 `src/api/interview.ts`，用 `uni.uploadFile` 调 `POST /qt/interview/apply`（**multipart**，不能走 `request.ts` 的 JSON）。
- 草稿（`handleSave`）继续本地 storage；只有「投递」换成真接口。
- 证件照：`uni.chooseImage` 后先 `uni.compressImage({ quality: 80 })` 再上传（后端图片档 5MB + 单边 ≤4096px）。
- 提交按钮 loading / 防重；失败把后端 `msg` 原样 toast（限流、重复提交、志愿相同都会靠这句话解释）。
- 性别：`男/女` → `"0"` / `"1"`。
- 志愿：中文 label → 字典 value，并补「安卓」。与管理端 `Quanta-admin-web/src/api/recruitment.js` 的 `departmentLabels` 对齐：

| 小程序选项 | 提交 value |
|---|---|
| 产品 | `PRODUCT` |
| 设计 | `DESIGN` |
| 全栈(前端) | `FRONTEND` |
| 全栈(后端) | `BACKEND` |
| 安卓（需新增） | `ANDROID` |

`uni.uploadFile` 不走 `request.ts` 拦截器：token（`Authorization: Bearer …`）、`code === 200`、401 跳登录、超时都要自己写。`request.ts` 目前没导出 `BASE_URL`，要么补一行 `export const BASE_URL`，要么在 `interview.ts` 里再取一次 `VITE_API_BASE_URL`。

### 1.2 流程页只读接后端

现状：`src/pages/freshman/join-us/process.vue` 读 `mockRecruitment.ts` 本地状态机。

- 投递内容/状态：`GET /qt/interview/my` → `data.application` + `data.profile`（含 `photoAccessUrl`）。
- 各轮结果：`GET /qt/interview/myResults`。两个志愿各有一轮记录，**按部门分轨**，不要当成单条时间线。
- 映射建议见待办 §2.3（一面 / 二面 / 录用）。
- **不要**把页面上的「接受 / 拒绝二面」接到 `PUT /qt/interview/admin/applications/{id}/join-status`（那是管理端权限）。本轮只展示 `interviewTime` / `feedback` / `resultStatus`；邀请按钮可隐藏，或 toast「请等待通知」。
- 杀小程序重进后流程页仍应显示已投递（数据在服务端，不是 storage）。

### 1.3 请求超时

`src/utils/request.ts` 默认 `timeout = 5000`。压测 P99 已到 2.7s，高峰偏紧。改为 **8000 或 10000**；`uni.uploadFile` 同样放宽。

### 1.4 验证码 UI（预留，不要求本周上线）

小程序登录页按 `GET /captchaImage` 返回的 `captchaEnabled` 显隐验证码（管理端已这样做）。后端当前关闭，先做不阻塞登录；**不要催后端立刻打开验证码**。

### 1.5 明确不要做

- 不要改任何 API baseURL / 生产域名。
- 不要在前端把图片 `http://` 替换成 `https://`（A1 已修，线上已是 https）。
- 不要做工位预约 / 图书 / 塔服其余 mock 页（与投递无关，另开任务）。
- 不要做微信登录或自助注册。

微信公众平台 → 开发管理 → 开发设置 → 服务器域名，都填 `https://www.quantacenter.com`：

证书已是 HTTPS（Let's Encrypt，约 2026-12-13 到期，服务器 certbot 自动续期）。

## 3. 验收（同学自测）

沿用待办 §3：

1. 用新生账号（如 `qt_fresh`）提交一份简历 → 提示成功；**杀掉小程序重进**后流程页仍显示已投递。
2. 管理端 `https://www.quantacenter.com/admin/` → 「招新管理」能看到这条；「阅览简历」里证件照能打开，URL 是 `https://`。
3. 同一账号再投一次 → 不产生第二条（更新），管理端看到最新内容。
4. 故意选两个相同志愿 / 不传照片 → 页面提示后端原始 `msg`，不是「投递成功」。

查库（密码见 `deploy/aliyun/.env`，勿贴群）：

```bash
docker exec -i quanta-mysql mysql -uroot -p'<见 .env>' -D 'ry-vue' \
  -e "select application_id,user_id,real_name,first_choice,second_choice,apply_status,photo_url,create_time from qt_interview_application order by application_id desc limit 5;"
```

小程序构建：`cd Quanta-uniapp && npx uni build -p mp-weixin`（产物 `dist/build/mp-weixin`，导入微信开发者工具上传体验版）。真接口联调用 production 模式，之前的 alitest 包作废。
