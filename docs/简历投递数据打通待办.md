## 2. 待办清单

### 2.1 小程序：投递改真实接口（必做）

`POST /qt/interview/apply` 是 **`multipart/form-data` 表单绑定**（不是 JSON body），所以必须用 `uni.uploadFile`，不能沿用 `src/utils/request.ts`。

参数拆法（字段名必须一致，Spring 按属性名分别绑到 `QtInterviewApplication` 与 `QtInterviewProfile`）：

- 进 `application`：`realName`、`gender`、`className`、`firstChoice`、`secondChoice`（已有照片时另传 `photoUrl`）
- 进 `profile`：`selfIntro`、`codingExperience`、`codingExperienceDesc`、`quantaUnderstanding`
- 文件：`name: 'photoFile'`

参考实现。注意 `src/utils/request.ts` 目前**只 `export default request`，`BASE_URL` 没有导出**（`:8`），所以要么给它补一行 `export const BASE_URL = ...`，要么在下面的文件里自己取一次环境变量：

```ts
// Quanta-uniapp/src/api/interview.ts（新建）
// 注意：本项目 vite.config.js 没有配 `@` 别名，现有代码一律用相对路径，这里保持一致
import { TOKEN_KEY } from '../utils/storage'          // TOKEN_KEY = 'token'

const BASE_URL = import.meta.env.VITE_API_BASE_URL || 'http://localhost:8080'

export const applyInterview = (filePath: string, form: Record<string, any>) =>
  new Promise<any>((resolve, reject) => {
    uni.uploadFile({
      url: `${BASE_URL}/qt/interview/apply`,
      filePath,
      name: 'photoFile',
      formData: {
        realName: form.realName,
        gender: form.gender === '男' ? '0' : form.gender === '女' ? '1' : '2',
        className: form.className,
        firstChoice: toDeptValue(form.firstChoice),
        secondChoice: toDeptValue(form.secondChoice),
        selfIntro: form.selfIntro,
        codingExperience: form.codingExperienceDesc?.trim() ? '1' : '0',
        codingExperienceDesc: form.codingExperienceDesc,
        quantaUnderstanding: form.quantaUnderstanding,
      },
      header: { Authorization: `Bearer ${uni.getStorageSync(TOKEN_KEY)}` },  // uploadFile 不自动带，必须手传
      success: (res) => {
        if (res.statusCode === 401) { /* 参照 request.ts 的 handleUnauthorized：清 session + reLaunch 登录页 */ }
        if (res.statusCode !== 200) return reject(new Error(`HTTP ${res.statusCode}`))
        const data = JSON.parse(res.data)
        data.code === 200 ? resolve(data) : reject(new Error(data.msg || '投递失败'))
      },
      fail: reject,
    })
  })
```

注意事项：

1. **`uni.uploadFile` 绕过了 `src/utils/request.ts` 的全部拦截**（自动带 token、`code === 200` 校验、401 跳登录、超时），上面这些都得在 `interview.ts` 里自己补一遍，别只写个 success toast。
2. 后端 `apply` 里 `application.setApplyStatus("SUBMITTED")` 是强制的，前端不用传 `applyStatus`。
3. `photoUrl` 与 `photoFile` 至少给一个，否则返回 `"请上传证件照"`；**重复提交按 user_id 更新**，不会重复插入。
4. 草稿（`handleSave` / `saveDraft`）可以继续留本地 storage，只把「投递」这一步换成真接口。成功后再写 `APPLICATION_SUBMITTED_KEY`。
5. 失败要把后端 `msg` 透出来（志愿相同、字典值非法、未登录等），别静默 toast「投递成功」。

### 2.2 小程序：志愿值必须映射成字典 value（必做，否则直接被后端拒）

后端 `QtInterviewController.java:48-49` 调 `QtDictUtils.requireValue(QtDictUtils.DEPT, ...)`，`DEPT = "qt_department"`。线上 `ry-vue.sys_dict_data` 实测：

| 小程序现有 `departmentOptions`（中文 label） | 应提交的 value |
|---|---|
| 产品 | `PRODUCT` |
| 设计 | `DESIGN` |
| 全栈(前端) | `FRONTEND` |
| 全栈(后端) | `BACKEND` |
| （小程序目前没有这一项） | `ANDROID`（安卓） |

- `src/utils/mockRecruitment.ts:5` 现在只有 4 个中文选项，**缺「安卓」**，且「全栈(前端)/全栈(后端)」与字典 label「前端/后端」不一致 → 需要加 `toDeptValue()` / `fromDeptValue()` 双向映射（管理端 `src/api/recruitment.js:4-10` 已有一份 `departmentLabels`，两边口径要对齐）。
- 更彻底的做法：小程序启动时拉 `GET /system/dict/data/type/qt_department` 动态渲染选项，避免再出现口径漂移。

### 2.3 小程序：流程页改读真实进度（必做）

- 投递内容/状态：`GET /qt/interview/my` → `data.application`（`applyStatus`: `SUBMITTED`/`PROCESSING`/`OFFERED`/`REJECTED`，含 `photoAccessUrl`）+ `data.profile`
- 各轮结果：`GET /qt/interview/myResults` → 数组，元素含 `roundName`（一面/二面/终面）、`department`、`resultStatus`（`PENDING`/`PASS`/`FAIL`/`WAITING`）、`score`、`feedback`、`interviewTime`、`publishedTime`
- `process.vue` 现有的 stage 状态机（`locked/pending/scheduled/passed/invited/accepted/declined/rejected/offered`）需要重写成一版「后端字段 → 页面状态」映射。建议映射（**需产品确认**）：

| 页面阶段 | 判定来源 |
|---|---|
| 一面 | `myResults` 里 `roundName=一面` 的 `resultStatus`；无记录且 `applyStatus=SUBMITTED` → 「待筛选」 |
| 二面 | `roundName=二面` 的 `resultStatus`；`interviewTime` 非空 → 「已通知」 |
| 录用 | `applyStatus`：`OFFERED`/`REJECTED`；`WAITING` → 待确认 |

- 两个志愿（`firstChoice`/`secondChoice`）会各自产生一轮记录，页面按部门分轨展示，别把 `myResults` 当成单条时间线。

### 2.4 后端：照片 URL 的协议（建议做）

`ServerConfig.getUrl()` 由请求自身推导。nginx 已经传了 `X-Forwarded-Proto`，但 `application.yml` 没开转发头策略，所以 HTTPS 访问下 `photoAccessUrl` 仍会拼成 `http://www.quantacenter.com/profile/...`（HTTPS 页面里的混合内容）。修法二选一：

- `ruoyi-admin/src/main/resources/application.yml` 的 `server:` 下加 `forward-headers-strategy: framework`（推荐）
- 或在 nginx 侧对 `/profile/` 单独处理，前端只存相对路径

### 2.5 微信后台配置（必做，运维/管理员）

微信公众平台 → 开发管理 → 开发设置 → 服务器域名，都填 `https://www.quantacenter.com`：

### 2.6 开放问题：投递者账号从哪来（需决策）

`/qt/interview/apply` 用 `getUserId()` 取当前登录用户，而小程序目前只有若依账号密码登录（`src/api/auth.ts:14` → `POST /login`；`auth.ts:5` 的 `VITE_USE_MOCK` 只控制「演示登录」，`.env.production` 里是 `false`，走真实登录），**没有微信授权注册链路**（后端也没有 appid/jscode2session 配置）。也就是说新生必须先有一个 `sys_user` 账号才能投简历。三个选项：

1. 招新前批量建账号（现在库里 `qt_fresh` 这类就是种子账号），把账号密码线下发给新生；
2. 后端补「微信登录 + 自助注册」，工作量最大；
3. 投递接口放开匿名（不推荐，`qt_interview_application.user_id` 唯一约束会失效，管理端也没法回溯到人）。

### 2.7 落库硬约束（动字段前先看，`sql/lab/lab_init.sql:258-281`）

`qt_interview_application`：

| 约束 | 影响 |
|---|---|
| `gender CHAR(1) NOT NULL` | 只能 `"0"/"1"/"2"`，小程序 `genderOptions=['男','女']` 必须转码后再传 |
| `first_choice / second_choice VARCHAR(16) NOT NULL` | 存字典 value（`FRONTEND` 等），传中文会因长度/取值不符出错，且管理端 `departmentLabels` 反查不到 |
| `CHECK (first_choice <> second_choice)` | 除后端校验外，DB 也会拦重复志愿 |
| `photo_url VARCHAR(255) NOT NULL` | 照片必须有落库路径 → 首次提交不带 `photoFile` 就必须带 `photoUrl` |
| `UNIQUE KEY uk_qia_user_id (user_id)` | 一人一份，重复提交是更新（配合 service 层 upsert） |
| `CONSTRAINT fk_qia_user FOREIGN KEY (user_id) REFERENCES sys_user(user_id)` | 投递者必须是真实 `sys_user`，见 2.6 |

`qt_interview_profile.application_id` 外键关联主表，`selfIntro / codingExperience / codingExperienceDesc / quantaUnderstanding` 存在这张表里，不在主表。

## 3. 验收标准

1. 小程序用新生账号提交一份简历 → 提示成功，且**杀掉小程序重进**后流程页仍显示已投递（说明数据在服务端而非 storage）。
2. 服务器查库行数增加、字段正确：
   ```bash
   docker exec -i quanta-mysql mysql -uroot -p'<见 deploy/aliyun/.env>' -D 'ry-vue' \
     -e "select application_id,user_id,real_name,first_choice,second_choice,apply_status,photo_url,create_time from qt_interview_application order by application_id desc limit 5;"
   ```
3. 管理端 `https://www.quantacenter.com/admin/` → 「招新管理」列表能看到这条，「阅览简历」弹窗里证件照能显示（照片 URL 是 `https://`）。
4. 用同一个账号再投一次 → 不产生第二条记录（更新），管理端看到的是最新内容。
5. 故意选两个相同志愿 / 不传照片 → 页面提示后端返回的原始 `msg`，不是「投递成功」。
