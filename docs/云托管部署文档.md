## 1. 环境发现（登录后先看有什么）

CloudBase 侧用 MCP 工具操作，先设备码登录：

```
cloudbase_auth(action=start_auth, authMode=device) → 打开 verification_uri 授权
```

关键探测结论（`envQuery(info)` + `queryCloudRun(list/detail)`）：

- 该环境内**已存在一组老服务**：`springboot-service`、`mysql-service`、`redis-service`、`postgres-service`、`agent-web`、`speaking-agent`、`ibot-map`（即参考项目 `ihavc-dev` 部署的）。它们的 MySQL/Redis **只对同环境内网可达、且不共享给外部**，本地机器无法直连（`Test-NetConnection ...:3306 → False`）。
- 因此本次 **另起一套隔离的 `quanta-mysql` / `quanta-redis`**，不复用老服务，避免数据串味。

> ⚠️ 云托管「同服务换镜像」有个坑：**服务名不能改**，只换镜像会沿用旧的构建名/内网域名。所以 MySQL、Redis、后端各自独立命名，互不影响。

### quanta-system/Dockerfile

```dockerfile
FROM eclipse-temurin:17-jre
WORKDIR /app
ENV TZ=Asia/Shanghai
RUN mkdir -p /home/ruoyi/uploadPath /app/logs
COPY ruoyi-admin.jar /app/ruoyi-admin.jar
EXPOSE 8080
ENTRYPOINT ["sh","-c","java -jar /app/ruoyi-admin.jar --ruoyi.profile=/home/ruoyi/uploadPath ${SPRING_ARGS}"]
```

> `--ruoyi.profile` 在镜像里固化（原 yml 是 Windows 路径 `D:/ruoyi/uploadPath`），避免上传目录写到不存在的位置。

### quanta-mysql/Dockerfile

```dockerfile
FROM mysql:8.0
ENV TZ=Asia/Shanghai
COPY initdb/ /docker-entrypoint-initdb.d/
```

> 依赖 **MySQL 官方镜像的 initdb 机制**：容器首次启动（空数据目录时）自动按序执行 `/docker-entrypoint-initdb.d/*`，用 `mysql` 客户端跑，天然支持 `DELIMITER` 触发器。重建服务=空目录=自动重导。

### quanta-redis/Dockerfile

```dockerfile
FROM redis:7-alpine
```

## 4. 建库 `ry-vue` 的几个坑（本次实际踩到）

1. **库名含连字符**：云托管 MySQL 建 `ry-vue`（带 `-`）。JDBC URL 用反引号/直连库名可，注意别拆错。
2. **种子 SQL 落后于代码**：`lab_full.sql` 是旧版，**缺 `sys_user.major`**（代码 `SysUser`/`QtLabMemberMapper` 已 `select u.major`）。首登报 `Unknown column 'u.major'`。→ 追加最新 `lab_init.sql`（内含 `major`）作为 `04`。
3. **`qt_activity_signup.remark` 缺列** → `lab_patch_signup_remark.sql` 作为 `05`。
4. **招新角色/菜单权限** → `lab_patch_qt_member_role.sql` 作为 `06`（幂等：`INSERT ... WHERE NOT EXISTS` / `INSERT IGNORE`）。
5. **补丁文件原为 GBK 编码**：两个 lab 补丁的中文注释里含单引号且是 GBK 字节，导入 utf8mb4 库报 `ERROR 1366 Incorrect string value: '\xCB\xFE...' for column 'role_name'`。→ 用 GBK(936) 读入、UTF-8(无 BOM) 写回后重导即好。

导入顺序=文件名字典序（01→07），`07` 最后执行，保证 `captchaEnabled=false` 不被前面脚本里的 INSERT 覆盖。

## 5. 部署（manageCloudRun deploy · 容器型/源码构建）

三个服务都用同一 MCP 入口 `cloudbase_manageCloudRun(action=deploy, serverType=container, targetPath=...)`。要点参数：

| 服务 | Port | CPU/内存 | 关键 EnvParams |
|---|---|---|---|
| `quanta-redis` | 6379 | 0.25 / 0.5 | `{}` |
| `quanta-mysql` | 3306 | 0.5 / 1 | `MYSQL_DATABASE=ry-vue`、`MYSQL_ROOT_PASSWORD`、`MYSQL_USER=quanta`、`MYSQL_PASSWORD`；`Cmd=--character-set-server=utf8mb4 --collation-server=utf8mb4_general_ci --default-authentication-plugin=mysql_native_password --log-bin-trust-function-creators=1` |
| `quanta-system` | 8080 | 1 / 2 | `MYSQL_HOST`/`MYSQL_PORT`/`MYSQL_USERNAME`/`MYSQL_PASSWORD`/`REDIS_HOST` 全部填**内网域名**、`SPRING_ARGS` |

`quanta-system` 的 `SPRING_ARGS`（覆盖 `application-druid.yml` 的 URL + Redis 索引）：

```
--spring.data.redis.database=1
--spring.datasource.druid.master.url=jdbc:mysql://<mysql内网域名>:3306/ry-vue?useUnicode=true&characterEncoding=UTF-8&connectionCollation=utf8mb4_general_ci&zeroDateTimeBehavior=convertToNull&useSSL=false&allowPublicKeyRetrieval=true&serverTimezone=GMT%2B8
```

- `useSSL=false + allowPublicKeyRetrieval=true`：MySQL 8 容器无证书。
- `spring.data.redis.database=1`：Redis 与老 `redis-service` 索引隔开防串（本次用的是独立 quanta-redis，但保留 db1 习惯）。

内网域名格式（同环境服务互访）：`gynmkzbt.<服务名>.d09wo6wa.dzk1bx5l.com:端口`。

### 部署顺序与观察

必须先 **mysql + redis 就绪 → 再 system**，否则 system 启动连不上。

`deploy(...)` 返回 `status:"deploying"` + 一个 `consoleUrl`；但**云托管构建是异步的**，MCP 不会同步等它好。轮询用：

```
cloudbase_queryCloudRun(action=detail, detailServerName=<服务>)     # 看 latestDeploy.Status / ServerConfig.InternalDomain
cloudbase_queryCloudRun(action=getDeployLog, buildId=<x>, detailServerName=<>)  # 看构建日志
cloudbase_queryLogs(action=searchLogs, service=tcbr, ...)           # 看容器 stdout / 应用启动日志(排障用这个)
```

`latestDeploy.Status`：`creating → normal`（成功）或 `build_failed` / `deploy_failed`（需看日志）。

### 实际踩到的两次部署失败

1. **`quanta-system` 首建 `build_failed`**：构建 OK、`COPY ruoyi-admin.jar` 也过，**最后推镜像给 CCR 时 `error from registry: blob unknown to registry`**（多分块推 `1a544406d75f` 后 blob 校验失败）。属平台/registry 偶发。→ **直接重新 `deploy` 一次**即成功（`configMerge` 会合并保留 `OpenAccessTypes`/EnvParams）。
2. **`quanta-system` 部署后 Pod `deploy_failed` + 应用启动崩溃**：`queryLogs` 抓到栈：
   ```
   captchaController → sysConfigServiceImpl → RedisConnectionFailureException ...
   Caused by: ...: Connection refused: gynmkzbt.redis-service...:6379 -> 172.16.85.71
   ```
   原因：**`redis-service` 是 `MinNum=0`（scale-to-zero），内网裸 TCP 不会自动唤醒**（区别于公网 HTTP 域名，域名不会拉起零实例）。而 `quanta-mysql` 当时 `MinNum=1` 常开没暴露。→ 新建 `quanta-redis` 独立服务 `MinNum=1`，把 `REDIS_HOST` 指向它，重启 `quanta-system` 后启动成功。
   > 经验：被其它服务当"数据库/缓存"用的云托管服务，**`MinNum` 至少=1（常驻）**，否则 scale-to-zero + 裸 TCP 内网访问会连不上。

> MCP `deploy` 里 `MISSING_VPC_FOR_DB_ENV` 警告：这是启发式提示（`MYSQL_*` 当外部云数据库），本场景是**自建 DB + TCP 服务**（非平台管理云数据库），可忽略。`quanta-mysql` EnvParams 里只是建 root/user 口令，不涉及连外部 DB。

## 6. 前端联调（招新小程序 `Quanta-uniapp` / uni-app vue3/vite）

- **baseURL 来源**：`src/utils/request.ts` 用 `import.meta.env.VITE_API_BASE_URL`；api 调用用干净路径（`/login`、无 `/prod-api` 前缀）→ 与后端 `context-path: /` 对齐。
- **生产 env**：`.env.production` 的 `VITE_API_BASE_URL` 改为上面的云托管域名。
- **构建产物**：`Quanta-uniapp/dist/build/mp-weixin`。
- **真机预览 "局域网失败转广域网"**：微信开发者工具预览优先走 PC/手机同 WiFi 直连拉包；不在同一网段/AP 隔离/防火墙会**降级走微信服务器中转（广域网）**，功能不受影响，只是首发慢。把手机和 PC 连同一路由即可。
- **合法域名**：`*.sh.run.tcloudbase.com` 为已备案的 HTTPS 域名，可在微信公众平台加到 request/downloadFile/uploadFile 合法域名；联调阶段可在工具里关「不校验合法域名」或 `project.config.json` 里 `urlCheck:false`。
- **AppID**：构建产物带的是游客 `touristappid`，只能模拟器；预览/真机需在开发者工具填自己申请的小程序 AppID，且该微信号需在该小程序「成员管理 → 体验成员」。

验证码：本次通过 `07_disable_captcha.sql` 在库层将 `sys.account.captchaEnabled=false`，`/captchaImage` 返回 `captchaEnabled:false`，小程序免验证码登录。**生产上线前记得把这条 initdb 脚本去掉/改回 true**。

## 7. 关停（本次收尾操作）

需求：关闭云托管服务 + 保留修改。用 `updateConfig` 热改 `MinNum=0`（容器缩容到 0、不常驻，不重新部署、不丢代码/镜像/配置）：

```
cloudbase_manageCloudRun(action=updateConfig, serverName=<服务>, serverConfig={MinNum:0})
```

**注意**：`quanta-system` `MinNum=0` 后，**内网裸 TCP（被小程序直连的后端 HTTP 域名仍会自动唤醒冷启）**，但因为本次把它连同依赖的 `quanta-mysql/quanta-redis` 一并置 0，下次要从外部跑通需先把依赖起回来：见 §9 恢复步骤。

## 8. 数据持久化方案与费用

### 8.1 本次决策（方案 A：**不加持久卷**）

- `quanta-mysql` `VolumesConf:[]`，容器重建/换版本 → 空 datadir → **initdb 全套自动重跑**（`01_ry_vue.sql` → `02_quartz.sql` → `03_lab_full.sql` → `04_lab_init.sql` → `05_patch_signup_remark.sql` → `06_patch_qt_member_role.sql` → `07_disable_captcha.sql`）。
- **等价于「关掉服务但保留数据」**：因为种子数据全部可复现、测试期无真实业务数据（用户已备份），"重新 initdb 得到的初态"和"上次跑完的状态"是一样的。
- 下次要用（见 §9）：`updateConfig(MinNum=1)` 起 `quanta-mysql`+`quanta-redis`，MySQL 空盘 → 数秒 initdb → 完事。**0 元数据保留成本**。
- 若之后**存了不可丢的生产业务数据**，走 §8.3 方案 B（迁移到 云开发 MySQL **自有账号**模式）。
- 未挂 CFS 的原因（同时说明为什么不推荐）：`manageCloudRun` MCP **只能挂载已存在的卷、不能创建卷**；且 MySQL InnoDB 挂 NFS/CFS 稳定性有官方警告，不适合真生产 DB。

### 8.2 计费口径（**权威数字**，来源：[CloudBase 资源点价格文档 2026-09-08](https://cloud.tencent.com/document/product/876/127357)，上海地域）

**核心换算**：1000 资源点 = 1 元；个人版套餐 **19.9 元/月**，含 **40,000 点/月**（≈ 40 元消费额度）。

| 资源 | 计费项 | 单价（元） |
|---|---|---|
| 云托管 | CPU | **0.055 元/核·小时** |
| 云托管 | 内存 | **0.032 元/GB·小时** |
| 云托管 | 外网出流量 | 0.8 元/GB |
| 云托管 | 默认域名 HTTP 调用 | 0.03 元/万次（HTTP 网关） |
| 内置·云开发 MySQL | 存储 | 0.0005 元/GB·小时（≈ 0.36 元/GB·月）|
| 内置·云开发 MySQL | 计算 | 0.342 元/核·小时（**个人版 默认自动暂停**：无请求 0 元） |

**当前 quanta 三个服务如果全部 `MinNum=1` 常驻 24×7×30 一个月的费用**：
- `quanta-mysql` (0.5C · 1G)：(0.5×0.055 + 1×0.032) × 720 h = **42.84 元/月**
- `quanta-redis` (0.25C · 0.5G)：(0.25×0.055 + 0.5×0.032) × 720 h = **21.42 元/月**
- `quanta-system` (1C · 2G)：(1×0.055 + 2×0.032) × 720 h = **85.68 元/月**
- **合计 ≈ 150 元/月**（会被 40,000 点/月个人版额度里扣掉 40 元，超出部分**按量付费或买资源包**）

**本次全部置 `MinNum=0` 后**：计算费 ≈ **0 元/月**（云托管只在实际有实例运行时收 CPU/内存）。有请求才冷启的秒级/分钟级使用不显著。

**测试一次实际消耗估算**（三服务同时起+访问 1 小时）：
- 1.75C × 0.055 + 3.5G × 0.032 = 0.09625 + 0.112 ≈ **0.21 元/小时**。
- 全部走 40 元/月免费额度，日常测 5 次/小时也才 1 元，不用额外付费。

### 8.3 备选方案 B：迁到「云开发 MySQL · 自有账号」模式（真·持久化）

未来需要跨重启保留业务数据时走这条。**本次不做**（因为业务数据不重要 + initdb 可复现 + 迁移需去控制台手动）。

流程：
1. **在云开发控制台手动**点：**数据库 → MySQL → 迁移至自有账号**（选/建 VPC+子网）。这一步**没有 API/MCP 化路径**，只能控制台点。
2. 迁移后拿到：TDSQL-C MySQL Serverless 实例的内网 `172.17.x.x:3306` + 明文 root/业务用户密码。
3. `quanta-system` 的 `SPRING_ARGS` 里 `--spring.datasource.druid.master.url` 指向新地址/新库；此时需要给 `quanta-system` 配 `VpcConf` 让它进入 MySQL 所在 VPC。
4. `manageMysqlDatabase initializeSchema`（或临时起 mysql-client 容器跑 initdb SQL）把 `ry-vue` 表灌进新实例。
5. 关掉 `quanta-mysql` 容器（`manageCloudRun delete` 或 `MinNum=0`）。

费用：0.36 元/GB/月 存储 + 按请求 CPU（Serverless 自动暂停）；RuoYi 空库 300MB ≈ **每月 <0.2 元** 存储费。
