## 2. 日志在哪

两套日志，用途不同，排障时两处都看。

### 2.1 logback（按级别拆文件）

路径默认 `/home/ruoyi/logs`（`ruoyi-admin/src/main/resources/logback.xml` 的 `LOG_PATH`）。按天滚动，保留 60 天。

| 文件 | 级别 | 看什么 |
|---|---|---|
| `sys-info.log` | INFO | 登录、限流、发码、`access-metric` |
| `sys-error.log` | ERROR | 未知异常、堆栈 |
| `sys-user.log` | INFO | 登录 / 注册 / 退出审计 |

当天文件无日期后缀；历史为 `sys-error.yyyy-MM-dd.log`。

### 2.2 Docker 控制台 + 文件（两套同时有）

Java 标准输出用 `tee` **同时**写入：

| 入口 | 路径 / 命令 | 看什么 |
|---|---|---|
| Docker 日志 | `docker logs -f --tail 300 quanta-app` | 启动横幅、Spring 控制台、未进 logback 的 stdout/stderr |
| 文件（持久） | `/opt/ruoyi/logs/stdout.log` | 同上，重启容器也还在 |
| 文件（持久） | `/opt/ruoyi/logs/stderr.log` | JVM 打到 stderr 的内容 |
| 备份脚本 | `/opt/ruoyi/logs/backup.log` | 每日 03:30 备份 |
| 证书脚本 | `/opt/ruoyi/logs/ensure-cert.log` | Let's Encrypt |

业务分文件仍在 `/home/ruoyi/logs`（见 2.1），`docker logs` **看不到** logback 的 `sys-info` / `sys-error`，那些只在文件里。

`docker logs` 受 json-file 限制：单文件约 20MB、最多 5 个滚动文件。更久的启动记录以 `/opt/ruoyi/logs/stdout.log` 为准。

旧的 `journalctl -u ruoyi` 只在回滚到 systemd 时有用。

### 2.3 重要口径

若依很多业务异常仍返回 **HTTP 200**，JSON 里 `code=500`。`access-metric` 的 `err5` 只认 HTTP 状态码，**不能**当 5xx 告警。要以 `sys-error.log` 和前端 `code` 为准。

2026-09-19 晚间报名接口连续写库失败时，`err5` 一直是 `0`。

## 3. 日常操作

以下命令在 ECS 上以 root 执行；本机也可用 `deploy/aliyun/upload.py`。

### 3.1 看状态

```bash
docker ps --filter name=quanta-
curl -sS http://127.0.0.1:8080/captchaImage | head
systemctl is-enabled ruoyi || true   # 切 Docker 后应为 disabled
```

预期：`quanta-app` / `quanta-mysql` / `quanta-redis` 在跑；MySQL/Redis healthy；验证码接口 `code=200`。

### 3.2 看最近日志

```bash
# Docker 控制台（与 stdout.log 同步）
docker logs --tail 300 quanta-app
docker logs -f quanta-app

# 同一份内容落盘，容器删了还在
tail -n 300 /opt/ruoyi/logs/stdout.log
tail -n 80  /opt/ruoyi/logs/stderr.log

# 业务 INFO / 访问指标
tail -n 80 /home/ruoyi/logs/sys-info.log

# 错误堆栈
tail -n 120 /home/ruoyi/logs/sys-error.log

# 登录注册审计
tail -n 50 /home/ruoyi/logs/sys-user.log

# 只盯未知异常
grep '发生未知异常' /home/ruoyi/logs/sys-error.log | tail
```

常用过滤：

```bash
grep -E '登录用户|register email|profile email|access-metric' /home/ruoyi/logs/sys-info.log | tail
grep -E 'interview/my|interview/apply|/login' /home/ruoyi/logs/sys-error.log | grep ERROR | tail
```

`access-metric` 每分钟一行，字段：`qps` / `avg` / `max`（毫秒）/ `err4` / `err5` / `inFlightMax` / `dbActive`。

### 3.3 重启后端（不发版）

```bash
cd /opt/ruoyi/deploy
RUOYI_UID=$(id -u ruoyi) RUOYI_GID=$(id -g ruoyi) docker compose up -d app --no-deps
docker restart quanta-app
# 约 40 秒后
grep 'Started RuoYiApplication' /opt/ruoyi/logs/stdout.log | tail -1
```

只重启 `quanta-app`。**不要** `docker compose down`，**不要**加 `-v`。登录 Token 在 Redis，一般不会全员掉线。改 `TOKEN_SECRET` 才会。

### 3.4 发版（jar + 可选门户）

在 Windows 仓库根目录：

```bash
mvn -pl ruoyi-admin -am clean package -DskipTests
cd deploy/aliyun
python upload.py sync     # 传 jar / run.sh / compose / backup.sh 等
python upload.py start    # 只重建/重启 quanta-app，失败会把 systemd 拉回来
python upload.py verify   # 本机 curl /captchaImage
```

注意：

- `start` 使用 `docker compose up -d app --no-deps` 或 `docker restart quanta-app`，**不会**重建 MySQL/Redis。
- `sync` 会覆盖服务器上的 `docker-compose.yml`。不要改 `mysql_data` / `redis_data` 卷名。
- 门户静态资源在 `/opt/ruoyi/admin/`，与 jar 分开同步。
- 启动成功日志类似：`Started RuoYiApplication in 40 seconds`。

### 3.5 依赖与备份

```bash
cd /opt/ruoyi/deploy && docker compose ps
docker logs quanta-mysql --tail 40
docker logs quanta-redis --tail 20

# 立刻打一份备份（口令从 /opt/ruoyi/.env 读取，不要写进聊天）
bash /opt/ruoyi/deploy/backup.sh

# cron：每天 03:30，保留 7 天
# 30 3 * * * /bin/bash /opt/ruoyi/deploy/backup.sh >> /opt/ruoyi/logs/backup.log 2>&1
ls -lh /opt/ruoyi/backups
```

产物：

- `/opt/ruoyi/backups/ry-vue-YYYYMMDD.sql.gz`
- `/opt/ruoyi/backups/uploadPath-YYYYMMDD.tar.gz`

磁盘占用超过 80% 时脚本只告警，不删业务数据。不备份 Redis（登录态可重建）。

停后端（库继续跑）：

```bash
docker stop quanta-app
```

停依赖（**不要**加 `-v`，否则删数据卷）：

```bash
docker stop quanta-app
cd /opt/ruoyi/deploy && docker compose stop mysql redis
```

回滚到 systemd：

```bash
docker stop quanta-app
systemctl enable --now ruoyi
```

## 5. 排障手册

### 5.1 服务起不来

1. `docker ps --filter name=quanta-app` → `tail /opt/ruoyi/logs/stderr.log`
2. `docker ps`：MySQL/Redis 是否 healthy
3. `tail /opt/ruoyi/logs/stderr.log`：缺 `TOKEN_SECRET`、连不上库、端口占用
4. `.env` 是否被 Windows 编辑带上 `\r`（`run.sh` 会剥 CR，但 profile 名异常时仍要检查）
5. 回滚：`docker stop quanta-app && systemctl enable --now ruoyi`

### 5.2 「招新信息加载失败」

1. `grep '/qt/interview/my' /home/ruoyi/logs/sys-error.log | tail`
2. 若仍是 `does not allow 'null' values`：确认 jar 含 `unless = "#result == null"`，并清 Redis 对应缓存
3. 页面会用空表单兜底，用户仍可能看到红字

### 5.3 报名提交失败

1. `grep '/qt/interview/apply' /home/ruoyi/logs/sys-error.log | tail`
2. `Data too long for column 'coding_experience_desc'` → 字段超过 500 字符
3. 临时：让用户缩短「编程经历补充」
4. 长期：`ALTER TABLE qt_interview_profile MODIFY coding_experience_desc TEXT;` 并在接口校验长度

### 5.4 验证码邮件没收到

`sys-info.log` 应有：

- 注册：`register email sent, studentNo=..., ip=...`
- 改邮箱：`profile email sent, userId=..., ip=...`

有这行说明 SMTP 已接受。没有则看 `sys-error.log` 是否 `MailSendException` / 限流 `rate_limit:register_email`。

### 5.5 登录提示走错入口

- 「该账号已是塔员，请使用塔员入口登录」
- 「该账号不是塔员，请使用新生入口登录」

这是 `loginType` 与 `is_quanta_member` 不一致，不是故障。

### 5.6 内存偏高

RSS 接近 1G 且 `Xmx=1024m` 时，先看 `access-metric` 的 `avg/max` 是否变差，再考虑重启释放堆。频繁 Full GC 会出现在 `stdout.log`。

## 6. 安全与配置开关

- 生产 `TOKEN_SECRET`、DB/Redis 口令只放 `/opt/ruoyi/.env`，权限 `600`，不要提交 git。
- `qt.cache.enabled`：业务查询缓存总开关，设 `false` 可立刻直查。
- Redis 业务库为 db1，缓存键前缀 `cache:`。
- 上传：证件照最大 10MB；校验文件头魔数与格式，**不限制像素**。文档 20MB。另受 Nginx `client_max_body_size 25m` 约束。
- 当前 `quanta-mysql` 映射了 `0.0.0.0:3306`。公网暴露数据库只应是临时排查，用完应收口到 `127.0.0.1`。
- Druid 监控默认关闭；不要对公网开放 `8080`。
- `qt.interview.applyOpen`：招新是否接受**新投递**。`false` 时从未报名的人会被 `POST /qt/interview/apply` 拒绝；已报名仍可改。改完后到「参数设置」刷新缓存。
- **关报名不等于关站。** `qt.metrics.enabled` 保持 `true`，访问指标、登录日志、Nginx、ARMS 继续采集。

## 8. 真实指标怎么取（只读，不导出个人信息）

关报名后仍要看访问量、登录和报名规模。任选下面一种即可，**只取统计结果**，不要导出姓名、学号、邮箱、照片或简历内容。

### 8.1 管理后台

- **访问指标**（权限 `qt:metrics:list`）：当前 QPS、延迟、错误率、近 24h 历史、热点 URI。接口：`GET /qt/metrics/latest|list|uris`。
- **登录日志**：`GET /monitor/logininfor/list`（Quanta 管理端暂无独立页面，可调 API 或直接用 8.2 聚合）。

### 8.2 SSH 生产 MySQL（最稳妥）

```bash
docker exec -i quanta-mysql mysql -uroot -p"$MYSQL_ROOT_PASSWORD" --default-character-set=utf8mb4 ry-vue \
  < sql/lab/lab_ops_metrics_readonly.sql
```

脚本里只有 `SELECT COUNT` / `GROUP BY`。会话已 `SET SESSION transaction_read_only = ON`。

### 8.3 ARMS 控制台

PV / UV / Session / 性能 / 异常以 ARMS 用户体验监控为准。前端 RUM SDK 尚未启用时，控制台可能没有浏览器端 PV；后端 Trace ID 仍可用于关联日志。操作见 [`Web端阿里云RUM与TraceID接入操作手册.md`](Web端阿里云RUM与TraceID接入操作手册.md)。

### 8.4 Nginx 访问日志

默认路径通常是 `/var/log/nginx/access.log`（本仓库 Nginx 配置未改 `access_log`，走系统默认）。

```bash
# 总请求量
wc -l /var/log/nginx/access.log

# 按路径粗算
awk '{print $7}' /var/log/nginx/access.log | sort | uniq -c | sort -nr | head

# 独立 IP 数（不能当成用户数：校园网出口会共享 IP）
awk '{print $1}' /var/log/nginx/access.log | sort -u | wc -l
```

**IP 数 ≠ 用户数。** 用户规模用报名表 `COUNT(*)` 或登录成功次数。
