## 5. 联调用的请求 / 响应要点

分页仍是 `TableDataInfo`：`{ code, msg, total, rows }`。  

AjaxResult：`{ code, msg, data }`。登录例外：token 在根上。

### 5.1 招新列表

```

GET /qt/interview/admin/applications?round=2&departmentId=BACKEND&status=PASS&pageNum=1&pageSize=10

```

也接受 `roundId`、`department`、`applyStatus`、`realName`。  

带 `round` 时 `status` 按**该轮结果**筛；不带 round 时按投递 `applyStatus` 筛。

rows 关键字段：`applicationId`、`userId`、`realName`、`studentNo`、`phonenumber`、`firstChoice`、`secondChoice`、`firstChoiceStatus`、`secondChoiceStatus`、`applyStatus`、`offeredDepartment`、`joinStatus`、`finalStatus`、`photoAccessUrl`、`createTime`。

详情：`GET /qt/interview/admin/applications/{id}` → `data.application` + `data.profile`。

### 5.2 面评

```

POST /qt/interview/admin/evaluations

```

JSON body：

- `applicationId`

- `roundId`

- `department`（BACKEND 等）

- `content`

返回含 `evaluationId`、`evaluatorName`、`createdTime`/`createTime`、`updatedTime`/`updateTime`。同一面试官同一志愿同一轮次重复提交为更新。

### 5.3 二面录用

```

POST /qt/interview/admin/offers

```

JSON body：

- `applicationId`

- `volunteerNo`：1 或 2，或直接传 `department`

- `decision`：仅 `PASS` 或 `OUT`

- `notice`：可选自定义通知文案

- `roundId`：可选，默认二面

两个志愿都 PASS 时 `offeredDepartment` 默认第一志愿。会写系统通知，`noticeStatus=SENT`。

### 5.4 招新看板

`GET /qt/interview/admin/statistics` 的 `data`：

- `submittedCount` / `processingCount` / `offeredCount` / `rejectedCount`

- `pendingEvalCount` / `pendingOfferCount` / `todayResumeCount`

非 CEO 自动按本部门统计。

### 5.5 宣讲会 / 分享会名单

响应**根级**（不是包在 data 里）：

| 字段 | 说明 |

|---|---|

| total | 报名人数 |

| quota | 活动名额 capacity |

| activityId / activityTitle / activityType | 活动信息 |

| rows | 名单 |

rows 含 `nickName`、`studentNo`、`major`、`phonenumber`、`signupTime`、`remark`。可选 Query `activityId`；不传则取该类型最新 `PUBLISHED` 活动。支持 `pageNum`/`pageSize`。

### 5.6 学习资料

上传：`multipart/form-data`，字段 `file`（必填）、`category`、`visibility`（ALL/MEMBER/DEPT，默认 MEMBER）、`remark`。

列表 rows：`materialId`、`fileName`、`fileSize`、`category`、`visibility`、`uploaderName`、`uploadTime`/`createTime`、`downloadUrl`（`/qt/materials/{id}/download`）。

### 5.7 确认收款

`PUT /system/order/{orderId}/approve`，无 body。成功后 `status=APPROVED`。非 SUBMITTED 返回 500 及中文 msg。

### 5.8 届次与留任

`GET /qt/member/cohorts` 的 `data`：

- `currentCohort`：届次对象（含 `cohortId`、`cohortName`、`isCurrent`）

- `cohorts`：数组，元素为 `id`、`name`、`isCurrent`（boolean）

留任：`PUT /qt/member/{userId}/retain`，body 至少 `{ "retain": true }`。可省略届次 id（默认当前届，必要时自动建下一届）。返回 `sourceStatus`、`targetRecord`、`createdCohort`。

## 6. Word 第 6 节：权限与数据范围（前端按钮要对齐）

角色 key：`ceo` / `qt_mgmt`（管理层） / `qt_manager`（经理层）。超级管理员 `admin` 视为 CEO。

| 能力 | 后端规则 | 前端注意 |

|---|---|---|

| 成员删除/重置/导入/留任 | 仅 CEO（注解 + 业务二次校验） | 非 CEO 不要展示这些按钮；打了也会失败 |

| 成员只读 | 有 `qt:member:list` 即可 | 管理层可看名单，不能留任 |

| 招新 | 非 CEO 只看本账号 `memberDepartment` 对应志愿 | 账号必须绑定成员部门，否则招新接口会报错 |

| 二面面评 | 经理层只能改本部门 **round 2** | 经理不要展示工位/塔服菜单（菜单已按角色裁剪） |

| 学习资料 | 上传/改/删校验权限或上传者；下载校验 visibility | DEPT 仅上传者同部门可见 |

| 后台 CRUD | 写操作已恢复 `@PreAuthorize` | 隐藏按钮不能代替鉴权，无权限会 403 |

部门枚举不要写死，拉字典：

- `/system/dict/data/type/qt_department`

- `/system/dict/data/type/qt_interview_round`

- `/system/dict/data/type/qt_apply_status`

- `/system/dict/data/type/qt_result_status`

- `/system/dict/data/type/qt_member_role`

- `/system/dict/data/type/qt_member_status`

- `/system/dict/data/type/qt_activity_type`

- `/system/dict/data/type/qt_material_visibility`

## 7. 前端联调顺序建议

1. 关 `VITE_USE_MOCK`，指向 `http://localhost:8080`。

2. C 端：登录、名录、活动、图书、工位、塔服、投递 —— 原路径不变。

3. 管理端：成员届次 tab → 招新列表/详情/面评/录用 → 确认收款 → 学习资料 → 控制台统计 → 宣讲会/分享会名单。

4. 用 `qt_mgmt` / `qt_manager` 账号验证部门隔离和按钮权限（需在用户管理里给账号绑角色和 `memberDepartment`）。

5. 登录取根上的 `token`，不要读 `data.token`。

6. 图片用 `effectImageUrl` / `qrImageUrl` / `photoAccessUrl` / `paymentProofUrl` 直接当 `img src`。

路径或字段冲突时以 **当前仓库 `docs/接口文档.md`** 为准，不要再按 Word 里的「缺失」去 Mock。
